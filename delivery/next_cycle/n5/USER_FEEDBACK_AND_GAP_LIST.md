# P1　色彩灰蒙蒙、不吸引人（用户第 1 条，最高优先）

## 问题

同一脚本统计 P1 三张与 n5b 正式图（`game_finalN5_formal_no_ui.png`）：

| 指标 | P1 t015 | P1 t084 | n5b | 判断 |
|---|---:|---:|---:|---|
| 平均饱和度 | 0.333 | 0.305 | **0.371** | 我们更高，**不是病因** |
| 色彩度（Hasler-Süsstrunk） | 0.145 | 0.126 | 0.119 | 略低 |
| 亮度标准差 | 0.207 | 0.228 | **0.187** | 对比不足 |
| 亮度 p95（高光上限） | 0.851 | 0.871 | **0.780** | **没有亮部** |
| 色相 0–30°（红橙）占比 | **0.73** | **0.70** | **0.06** | **几乎为 0** |
| 色相 30–60°（黄橙）占比 | 0.21 | 0.26 | **0.90** | **过度集中** |

**根因（三条叠加）**

1. **色相整体偏黄约 30°**：P1 的暖是红橙（0–30°），我们 90% 落在黄橙（30–60°）。黄橙高饱和在视觉上就是"土、闷"。
2. **没有高光**：p95 只有 0.780，画面缺最亮的 5%，所以像蒙了一层灰。
3. **我在 n5 加的线性雾过重**：`fogStart=26 / fogEnd=72`，把中远景统一压向灰绿；加上为修暗带引入的
   `leaf_haze #A3A78F`、`leaf_mid_haze #8A8F74`（色相 70–71°，本身就是灰绿），进一步去色。

## 解决方案

### 1) 调色板整体向红橙推（`tools/blender_n5/courtyard_lib.py` 的 `PALETTE`）

| 键 | 现值 / 色相 | 改为 / 色相 | 说明 |
|---|---|---|---|
| `leaf_ochre` | `#D3A24C` / 38.2° | **`#CF7F33` / 29.2°** | 主叶色 |
| `leaf_amber` | `#BE7A3A` / 29.1° | **`#B85E22` / 24.0°** | 暖叶 |
| `leaf_gold` | `#E0C068` / 44.0° | **`#DB8034` / 27.3°** | 高光叶 |
| `leaf_deep` | `#746337` / 43.3° | **`#77401F` / 22.5°** | 暗部叶 |
| `leaf_olive` | `#7D8C4E` / 74.5° | **`#6B7038` / 65.4°** | 保留作冷调和，降饱和降亮度 |
| `leaf_mid_haze` | `#8A8F74` / 71.1° | **`#9A8660` / 39.3°** | 远景不再发绿 |
| `leaf_haze` | `#A3A78F` / 70.0° | **`#B5A47E` / 41.5°** | 同上，改暖灰 |

同值同步到引擎 `demo_n5/assets/scripts/CourtyardBootstrap.ts` 的 `MAT_OVERRIDES`。

### 2) 抬高光

- `tools/blender_n5` 与 `CourtyardBootstrap.ts` 的 key 光：**112000 → 135000**
- 若 p95 仍不足，把 key 色从 `#FFCC96` 提到 **`#FFD6A8`**（更亮的暖白）

### 3) 收雾

- `fogStart` **26 → 38**，`fogEnd` **72 → 90**
- 雾色 `(201,194,176)` → **`(214,196,168)`**（更暖，不再压向绿灰）

## 结果（验收标准）

- 同机位正式图上：**色相 0–30° 占比 ≥ 0.35**（现 0.06）
- **亮度 p95 ≥ 0.84**（现 0.780）
- **色彩度 ≥ 0.13**（现 0.119）
- 饱和度不得低于现值的 90%（避免为了改色相把颜色洗掉）
- 肉眼判据：与 P1 并排时不再读作"蒙灰/土黄"

复跑方式：对 P1 三张与 n5c 正式图跑同一统计脚本，数值与主观判断同时记录，两者不一致时以**肉眼**为准并说明原因。

# P2　树冠中间一坨绿（用户第 2 条）

## 问题

`delivery/next_cycle/n5/T4/_zoom_crown.png`（正式图 2 倍放大）可见**两块光滑、无贴图的灰绿色椭球**浮在树冠里，
颜色 `#68705E`（色相 71°）与周围黄橙叶团完全不协调。

**根因**：`build_env_courtyard.py` 的 `create_tree()` 用 5 个 `add_mass_lobe` 生成光滑椭球作"内芯"，
设计前提是"永远被叶子盖住"。n5 采用变体 C 后叶量下降，前提失效，内芯暴露。
n5b 我把它改成灰绿并缩小 18%——**只是让"褐色光头"变成"绿色一坨"，方向错误**。

## 解决方案

取消"靠遮挡才成立"的可见实体，改用**叶子自身**堵缝：

1. **删除** `create_tree()` 中 5 个 `add_mass_lobe` 循环（连同 `mass_bm` 的生成与 `finish_mesh`）。
2. 在原内芯位置新增**内层叶簇壳**：以树冠中心为球心、半径 0.55R，放 **34 个叶簇 × 10 张叶卡**，
   调色板取 `leaf_deep/leaf_amber`（红橙暗部），`shell_inner=0.25`（让卡完全在外侧）。
3. `crown_mass` 对象不再导出（引擎侧不需要这个网格）。

预期三角面：-5 个椭球（约 3k）+ 34×10 张卡（约 9k），净增约 **+6k**，相对当前 1.42M 可忽略。

## 结果（验收标准）

- 渲染 **4 个机位**（前 / 后 / 左侧 / 游戏机位），任何角度**不得出现可辨认的光滑色块**
- 纯黑剪影中，树冠内部无"实心球"边界，只有叶缘
- 总三角面增幅 ≤ 2%
- 4 张验收图存 `T4/P2_crown_views/`，并配一张 n5b 对照图

# P3　石砖上长草（用户第 3 条）

## 问题

`delivery/next_cycle/n5/T4/_zoom_paving_grass.png`：画面中部有一整丛草直接长在砖面中央，
另有大量草叶从砖缝钻出、沿花坛外沿长到砖上。

**根因（已定位到行）**：`tools/blender_n5/build_map001.py`

- **第 801–807 行**：花坛草只检查了**花坛中心** `on_paving(bx, bz)`，随后 45 株在花坛范围内 `gx, gz` 自由散点，
  **没有逐株判定**。花坛与铺装模块一重叠，草就直接长到砖面。
- **第 62 行** `on_paving()` 依赖 `PAVING_CENTERS`（模块中心），铺装实际覆盖比该列表大时，边界砖面被判为"非铺装"。

## 解决方案

1. **逐株判定**：把 `on_paving` 作为参数传进 `_add_turf_patch()`，在**每一株**草生成前检查其基点；
   被挡的株直接跳过并计入 `skipped`，而不是整片放弃。
2. **用实际覆盖替代中心列表**：由 `PAVING_CENTERS` 与 `PAVING_HALF` 生成矩形列表，
   `on_paving(x,z)` 改为"点落在任一矩形内（含 inset）"，覆盖范围与真实铺装一致。
3. **产出审计文件**：构建时写 `art/candidates/candidate_n5/vegetation_audit.json`，
   记录每株草的 `(x, z, on_paving)` 与总计数。
4. **新增可复跑检查** `tools/n5_check_vegetation.py`：
   读审计文件，输出 `violations`（根点落在铺装上的株数）。
   **必须先把 n5b 当前版本作为失败样本跑一次，确认它报 >0**，否则检查本身可疑。

## 结果（验收标准）

- n5c 审计：`violations == 0`
- n5b 失败样本：`violations > 0`（证明检查有效）
- 视觉：砖面中央不再出现孤立草丛；砖缝可有零星草叶，但**不得超过砖面面积的 2%**
- 检查脚本与两份审计文件入包

# P4　铺装深色砖像随机污渍

## 问题

铺装上的深色砖是**孤立、随机分布**的单块，读起来像脏点而不是"修补"或"功能区划分"（见 `_zoom_paving_grass.png`）。

## 解决方案

把随机单块改为**有组织的成组**：

1. 每个模块按变体号确定性地放置 **1 组修补**（2–4 块相邻深色砖，形成矩形或 L 形），而不是逐块随机。
2. 沿花坛外沿与长椅下方加 **水渍带**（低对比、边缘不规则的深色多边形）。
3. 加 **3–5 条裂缝**：沿砖缝走向的细深色四边形（宽 2–3 cm），跨 2–3 块砖，不随机散点。

## 结果

- 深色砖**成组率 ≥ 90%**（单块孤立深色砖占比 ≤ 10%）
- 裂缝在游戏视距可见（对比度 ≥ 8 灰阶）
- 与 P1 t084 并排：铺装读作"被使用过的场地"而非"脏了的地砖"

# P5　裸土是一整片无纹理平色

## 问题

大面积土壤是均匀的 `#6B5B47` 平色，没有任何颗粒、湿度变化或碎屑，占据画面两侧相当大的面积。

## 解决方案

1. 土壤材质噪声尺度从低频改为**双频**（大尺度湿度斑 + 高频颗粒），对比度提高。
2. 在土壤区投放**碎石、落叶、枯枝**三类小物件（各 40–60 个，成簇分布，不成均匀散点）。
3. 花坛边缘加一圈**土-石过渡带**（深浅过渡 + 少量小石子），避免生硬的直线边界。

## 结果

- 土壤区域亮度标准差 ≥ 0.05（现约 0.02）
- 土壤上无大面积（>1 m²）完全均匀区域
- 与 P1 并排：土壤有"可踩"的质感而非色块

# P6　远景土丘是光滑灰色块

## 问题

n5b 新增的 9 处远景土丘是无贴图的光滑椭球，颜色 `#8A8F74`，读作"塑料山"。

## 解决方案

- 土丘表面加叶簇（每处 12–18 个，`leaf_haze`/`leaf_mid_haze`），破掉光滑边界
- 三角面预算：9 × 15 簇 × 6 卡 ≈ 800 面，可忽略
- 若仍显块状，把 `flatten` 从 0.32 提到 0.45 并加大 `displace`

## 结果

- 远景层在 1280×720 下**不出现连续 >40 px 的光滑边缘**
- 与 R2 的顶部条带指标同时复核（不得把暗带重新变回来）

# P7　树冠叶稀、呈蘑菇形

## 问题

叶片呈散点状，叶团之间成片空枝，冠形上重下空（`_zoom_crown.png`）。

## 解决方案

1. 外层再加一层壳：现有 84 簇之外，在外缘 `0.95R` 加 **26 簇**，尺寸偏小（0.6–0.8），只做轮廓破形。
2. 中段（z 2.8–3.6）补 **18 簇**，直接解决"蘑菇裙"问题。n5b 虽已偏向低枝锚，但数量不足且未验证。
3. **先渲剪影验收**，通过后再进地图，不要直接打整包。

## 结果

- 剪影中，树冠在 z 2.8–3.6 区间的叶覆盖宽度 ≥ 最大冠幅的 60%
- 游戏机位下，叶团之间不再出现 >0.4 m² 的连续空枝
- 三角面增幅 ≤ 15%（当前 194k → 上限 223k）

# P8　UI 比 P1 重

## 问题

P1 t044/t084 的任务卡与对白是**细线 + 半透明浅带 + 少量 doodle**；
我们是**厚纸（alpha 246）+ 胶带 ×2 + 大面板**。前几轮我一直往纸上加装饰，方向与参考相反。

## 解决方案

1. 面板 alpha **246 → 200**，内衬 alpha **214 → 170**
2. 每个面板胶带 **2 → 1**
3. doodle 数量 **4 → 2**（只保留头像附近与按钮附近各一）
4. `deckleOutline` 线宽与透明度各减半
5. 字号层级保持 n5 的 34/24（已达标），不再加大

## 结果

- 与 t044 并排：面板的**不透明面积占比**接近参考（目标 ≤ 参考 + 10%）
- 小字可读性不下降（在 1280×720 与 720×1280 各验一次）
- UI 卡得分中 `typography`/`doodle_icon_family` 有实证支持再提分

# P9　缺前景遮挡，铺地完整暴露

## 问题

P1 t084 用楼梯、栏杆、桶、花坛切掉近一半铺地；我们的铺地从前到后完整暴露，
这是"网格感最重"的直接原因，也是 `composition_scale` 停在 3 的实证。

## 解决方案

在画面**下缘**加一组前景遮挡（不进入可行走区、不加碰撞）：

- 一段低栏杆（复用 `ENV004`）+ 2 个水桶（复用 `PROP004` 衍生）+ 3 丛高草
- 位置在下缘 y ≈ 690–720，遮挡画面 **8%–15%**
- 保持角色与交互按钮不被遮挡

## 结果

- 铺装占画面面积从当前约 52% 降到 **≤ 45%**
- 角色屏幕包围盒不被遮挡（Q01 复核）
- 与 t084 并排：画面下缘有实体，而不是一路平铺到边
