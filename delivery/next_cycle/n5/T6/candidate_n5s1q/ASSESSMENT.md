## 固定参考逐区对比和修复验收

1. **镜头/构图**：P1 的左下阶梯、大块平台和中景角色形成清楚的近—中—远层；s1q 固定截图主要是大块庭院地面，阶梯没有进入主视觉，树与远处叶墙占比过高。先按 t084s 的 16:9 画面标注前景阶梯、角色落点、平台边线、远景边界四个构图框，再动相机或物件。验收：保持角色 86–130px，阶梯至少形成左下约 20–30% 高度的前景引导，树冠不切断角色轮廓，远景地平线压低；正式三图共享同一相机。
2. **地面**：P1 为大型石板，接缝宽度和透视统一，局部只有少量自然磨损；s1q 地砖网格过密、直线过于规整、颜色平且空白面积大。固定一个石板基模与接缝宽度，变体只作用于边缘缺口/轻微色差，减少地面重复线；在 Blender 中用节点控制粗糙度、低频污渍和接触暗部。验收：全景同一块砖尺度连续，接缝不出现不同尺寸体系，角色脚下有柔和接触影。
3. **树冠/枝叶**：P1 树冠由可读枝干和细叶形成自然轮廓，远处柔焦；s1q 大片锐角叶片重叠成碎裂边，且前景树体过大。先做主枝骨架，再用三种尺度的叶片卡按枝向分布，限制单片法线/角度的突兀高光；远景叶片用低对比材质，保持画面预算。验收：缩至 50% 仍读出枝干方向和完整树冠边缘，角色头部周围留出清楚剪影。
4. **草丛**：P1 的草是种植池中连续的金色簇状体，有高低层；s1q 更像零散尖三角片和重复草线。用 Blender 几何节点/程序化原生网格做“基部密、顶端疏”的簇，按花池边缘成片布置，做高度和色相分组；石板上禁止散点。验收：前中景各有可读簇群，远景密度递减；俯视/近景 audit 不允许落在铺地上。
5. **光色**：P1 暖色、漫反射和景深共同压低远景对比；s1q 阳光与树影边缘硬，地面偏单一黄褐。主光使用暖侧光，世界填充略偏冷/中性，阴影减硬；只在远景做轻微雾化/景深，角色仍清晰。验收：角色、石材、树叶来自同一光照方向；树影可辨但不能成为黑色硬剪影；避免全屏统一黄滤镜。
6. **设施和交互 UI**：P1 有阶梯栏杆、花池、旗串等细节与手绘任务符号；s1q UI 纸张面积和信息可读，但边框、按钮、任务面板过规整，交互符号风格分散。先统一纸边 SVG/可编辑矢量、铅笔线宽、图标家族和墨色，再做任务接受/收集/完成三态；把花池边缘、栏杆、阶梯作为构图设施，不靠堆挂饰补细节。验收：无 UI 主画面成立；开 UI 后不遮挡角色和路线；对白若改机位，单独留对白相机参数，不混入 Q01 同机位正式三图。

## 失败反例和原因

- `delivery/performance/20261027T184635Z_4533b4d3`：Blender 首次 s1r 导出因叶片 atlas 使用相对路径，实际读取 `C:\软件\鼠鼠\textures\tex_leaf_atlas.png` 失败。保存的原生 `.blend` 保留；随后用临时 atlas 路径成功导出，失败记录不删除。
- s1r GLB 124,712,900 bytes、1,143,443 triangles，相对 s1q GLB 72,651,240 bytes、716,463 triangles 增长约 71.7% / 59.6%。共同原因是 s1q 隐式用了 `N5_LEAF_COUNT_SCALE=0.5`、`N5_GRASS_COUNT_SCALE=0.58`，s1r 没记录并按代码默认密度生成。正确修复是把构建参数显式写进候选环境清单和 Blender 导出命令，先运行几何预算检查，再导出；禁止依赖 shell 残留变量。
- `captures/q06_stats_stale_reference_failed.json`：曾把 n5 的 GLB hash/字节数误挂到 s1q 的运行统计。已保留为失败证据，并以 s1q 实际 GLB hash/size 纠正当前 q06 记录。
- 当前项目体积 `16,117,321,161 bytes`，比 15 GiB 上限超 `11,193,801 bytes`。启动下一次约 160 MiB Cocos build 会增加超限，因此在空间恢复前不再执行大构建/导出。已尝试清理的只是可重建缓存 `demo_n5s1/build_s1i`、`build_s1j`、`build_s1n`、`build_s1o`（保留对应源、截图、日志），自动审批对递归删除操作返回 `blocked by policy`；没有换命令绕过。旧版 s1r 大 GLB也完整保留，当前尚无法清理。
