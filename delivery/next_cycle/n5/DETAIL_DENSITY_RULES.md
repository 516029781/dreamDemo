## 一、结论：不是"细节不够"，是"细节过碎"

用同一脚本比较 P1 三帧与 n4/n5b 正式图（统一缩放到 1280×720 灰度）：

| 指标 | P1 t015 | P1 t084 | P1 t030 | P1 均值 | n5b 我们 | 相对差 |
|---|---:|---:|---:|---:|---:|---|
| 平均梯度幅值 | 0.0285 | 0.0297 | 0.0220 | **0.0267** | **0.0426** | 高 60% |
| 梯度 p90 | 0.074 | 0.082 | 0.056 | **0.071** | **0.128** | 高 80% |
| 边缘像素占比（>0.10） | 6.1% | 7.7% | 4.8% | **6.2%** | **14.8%** | **2.4 倍** |
| FFT 低频（r≤0.15，大形） | 0.317 | 0.281 | 0.284 | **0.294** | **0.164** | 少 44% |
| FFT 中频 | 0.278 | 0.276 | 0.245 | 0.266 | 0.182 | 少 32% |
| FFT 高频（r>0.35，碎细节） | 0.406 | 0.443 | 0.471 | **0.440** | **0.653** | 多 48% |

**判读**：我们的画面能量集中在高频（碎细节），参考集中在低中频（大形块）。
不是我们"缺少内容"，而是**内容被切得太碎**，视觉上无法形成可读的大形。

这也解释了为什么前几轮"加细节"越加越糟：每加一层小元素，高频能量继续上升，画面更乱。

## 二、具体碎在哪（逐项清点）

| 元素 | 现状 | 碎的原因 | P1 的做法 |
|---|---|---|---|
| 铺装 | 0.5 m 小砖，16 个模块，每块独立倒角+接缝 | 接缝数量多 → 画面布满高频直线 | 0.9–1.4 m 大板，接缝少且与砖同色 |
| 草 | 每株 4–6 片细叶，成百上千株 | 叶宽 2–3 cm，在 1280 宽画面里不足 3 px | 成团、叶更宽、整体读成"一片草" |
| 树叶 | 叶卡 0.085–0.125 m，上千张 | 单片小于 6 px，形成噪点状冠 | 叶团成块，单片更大，靠明暗分团 |
| 碎石/落叶 | 46 颗石子 + 成片落叶散点 | 随机散布小点 | 极少，且集中在边缘 |
| 远景土丘 | 9 处小丘 | 体量小、数量多 | 2–3 个大体量远景 |
| 道具 | 长椅、灯、花坛各自孤立且偏小 | 小体量散布 | 大件、成组、有明确剪影 |

## 三、规则（n5c 起强制）

### D1　大形优先：任何元素"在 1280 宽画面里小于 X px"就不该被单独看见

| 元素 | 最小可读尺寸 | 做法 |
|---|---|---|
| 铺装板块 | ≥ 120 px（约 1.2 m） | 板尺寸 0.5 → **1.2 m**，模块内板数减少约 60% |
| 草叶宽度 | ≥ 4 px | 叶宽 2–3 cm → **4–5 cm**，同时株数减半 |
| 树叶单卡 | ≥ 8 px | 0.085–0.125 m → **0.16–0.22 m**，张数减 35% |
| 碎石 | ≥ 6 px 或删除 | 46 → **12**,且只在花坛/路缘 |
| 远景丘 | ≥ 200 px | 9 → **3**,单体放大 |

### D2　同类元素必须成团，不做均匀散布

- 草：以 1.2–2.0 m 的团块为单位投放，团内密集、团间留空
- 落叶：集中在花坛边缘与路缘，3–5 处成片，不做全图散点
- 石子：同上

### D3　接缝/缝隙对比度不得超过砖面明度的 12%

- 参考实测：受光砖 `#DBC2A8`（明度 0.76）与接缝差异很小
- 我们现状：接缝比砖暗约 40%，形成网格
- 目标：接缝明度 ≈ 砖面 − 8%–12%

### D4　细节只放在"焦点走廊"

- 允许高细节：角色附近 3 m、交互物（留言板/花坛/长椅）周边
- 其余区域：只保留大形与材质变化，不加小装饰

### D5　每条新增元素必须回答"它在画面里占多少像素"

小于阈值的元素一律合并或删除，不允许以"更真实"为理由保留。

## 四、验收指标（写进 n5c）

| 指标 | 目标 | 现值 |
|---|---|---|
| 边缘像素占比 | **≤ 8.5%** | 14.8% |
| 平均梯度 | **≤ 0.032** | 0.0426 |
| FFT 高频能量 | **≤ 0.50** | 0.653 |
| FFT 低频能量 | **≥ 0.26** | 0.164 |
| 铺装板块边长 | ≥ 1.1 m | 0.5 m |
| 草叶最小屏宽 | ≥ 4 px | 约 2–3 px |

同时不能牺牲：
- 角色可读性（Q01 包围盒不变）
- 交互物可辨识（留言板、花坛、长椅）
- 树的层次（枝→叶团仍要能读）

预期副作用（正向）：draw calls 与三角面下降，Q06 成本改善。

## 五、与其它批次的关系

- **B1 色彩**：色相/光照照旧，但**饱和度分配**要按"大形才有色彩，碎细节降饱和"执行，否则高频碎点仍会抢眼
- **B3 树**：叶卡从 0.085–0.125 m 放大到 0.16–0.22 m，簇数相应下调（不是简单减半，按剪影验收）
- **B4 铺装/土壤**：板块放大、去掉随机深色砖、裂缝改为少数几条主干裂缝（不是密集细纹）
- **B5 UI**：UI 不受影响（UI 元素本就不碎）

## 六、复跑命令

```bash
python - <<'PY'
from PIL import Image
import numpy as np
def probe(p):
    a=np.asarray(Image.open(p).convert('L').resize((1280,720),Image.LANCZOS),dtype=np.float32)/255.0
    gy,gx=np.gradient(a); mag=np.hypot(gx,gy)
    F=np.fft.fftshift(np.abs(np.fft.fft2(a))); h,w=a.shape; cy,cx=h//2,w//2
    y,x=np.ogrid[:h,:w]; r=np.hypot((y-cy)/cy,(x-cx)/cx); tot=F.sum()
    return dict(grad=round(float(mag.mean()),4),
                edge_pct=round(float((mag>0.10).mean()*100),1),
                lo=round(float(F[r<=0.15].sum()/tot),3),
                mid=round(float(F[(r>0.15)&(r<=0.35)].sum()/tot),3),
                hi=round(float(F[r>0.35].sum()/tot),3))
PY
```
