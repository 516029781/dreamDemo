## 交付次序与最小修改面

| 工作单 | 先改什么 | 低成本预览及关闭证据 | 失败后下一步 |
|---|---|---|---|
| N01 几何 | 主树：分枝有粗细递减，树冠大中小团簇错开；清除悬浮叶卡与显眼重复角面。再修绿篱前后深度、花坛外缘、长椅/栏杆厚度和倒角。优先改共享 Blender 母版/生成参数，保留道路和角色坐标。 | 固定正式镜头原尺寸图，加主树、绿篱、花坛/长椅三类近景；与 n2 和 P1 `t015s` 同区域并列。正式画面不再被明显的低模重复形状和大片空铺地支配；`geometry_craft ≥3/4`，`vegetation_depth ≥3/4`，可编辑源可重开。 | 若三轮只调随机种子仍无改善，改枝干拓扑/叶簇实例规则和场景布局，再预览；不能靠远景模糊遮盖。 |
| N02 材质/光 | 在石、木、金属三套共享材质中分别建立明度、粗糙度、边缘/污渍的尺度变化；土面与铺地过渡有层次；先调整填充与物体接触，再考虑阴影精度。 | 同机位全景和石/木/金属近景；材质可在游戏视距区分、树/长椅/人物脚底有接触层次，`material_separation ≥3/4`、`lighting_contact ≥3/4`。记录阴影参数与桌面成本；微信真机未测时只能记风险，不能宣称达标。 | 如扩大阴影图只让桌面变清楚而成本升高，退回并改局部接触阴影/材质；先定位光源/色彩空间问题。 |
| N03 UI | 从同一个纸面 SVG/布局母版修改任务卡、对白、右下按钮：减少嵌套矩形和实色面积，边缘与涂鸦笔触成一家，文字对比稳定。对白优先减高度/留白，保持内容和触控可读。 | `formal_ui`、`dialogue`、暂停、竖屏原尺寸图，P1 `t044s/t084s` 并列；对白面板初始目标占 720 高度约 24–27%，以可读性/不遮主角为最终判断。`paper_shape ≥3/4`、`doodle_icon_family ≥3/4`，文字不截断，状态反馈不退化。数值是布局工作目标，不是 rubric 新门禁。 | 若仅调透明度仍显得像标准卡片，改轮廓/层叠/图标笔触规则；不要给每张状态图单独贴装饰。 |
| N09 恢复行为 | 分开“恢复”和“重新开始”：恢复只解锁输入并维持玩家世界坐标、任务、对白/板状态与相机目标；重新开始才重置位置。清除暂停前按住的输入，竖屏返回横屏也不能暗中重开。检查 `demo/assets/scripts/CourtyardBootstrap.ts` 中 `setPause(false)`、`resetView()` 与竖屏返回调用链。 | 从出生点以键盘、触控各移动至少 0.5 m 后记录位置/状态/相机；暂停期间键盘和触控均零位移；无新输入恢复后位置差在测量容差内（建议 ≤0.02 m），任务/相机连续；新输入可再次移动。横屏→竖屏→横屏从非出生点重复。保存画面、坐标、事件与执行结果。 | 若仅从出生点通过，视为未覆盖；若输入粘连，先拆输入状态机，再重测。不可用测试脚本直接设玩家位置或目标 UI 状态制造通过。 |
| MIX 融合 | 等 N01–N03 首轮收敛后，同一镜头同一时刻联合调整场景细节密度、人物脚底接触、树前后遮挡、亮暗关系和 UI 注意力；锁定角色身份与动画源。 | 全景无 UI / 有 UI / 对白三张，固定相机与角色位置；与 P1 相应区域并列。`visual_language`、`color_light_coherence`、`world_style_coherence` 均 ≥3/4，且角色/路径/按钮可读。 | 若低模背景与角色仍割裂，回到 N01/N02 共享原因，不能只叠 FX/滤镜。 |

上述 `≥3/4` 是针对本轮失分维度的制作检查点，不替代完整候选的正式门槛：制作侧 ENV/CHAR/UI/MIX **各 ≥90**、核心维度 ≥3/4、任何维度 ≥2/4、Q/绑定通过、未解 blocking/major 为 0。不能为凑 90 分改自评分；达不到就保留真实分数和未解项继续返修。

## 执行循环

1. 先固定 n2 的原图、P1 对应区域和失败截图，不改 n2。制作工作区建立新候选，记录起点哈希、缺陷 ID、受影响源/导出/场景/状态图/Q 项；未变依赖可复用，不能拿旧截图配新构建。
2. N01 用母版的局部快速预览判轮廓，N02 复用同一场景调材质与接触，N03 复用 UI 组件做状态图；N09 可同时修，但进入整包前必须从非默认状态跑通。每次预览都看 P1/上一轮/本轮同机位图，写一行“观察差异→修改→结果”。
3. 出现明显几何角面、对白遮挡或恢复回跳时立即返修，不进行完整截图矩阵和 ZIP 打包。达到上述局部关闭标准后才做受影响构建、真实事件采集、Q01–Q09、绑定和全量覆盖检查。
4. 制作侧用实际原图逐维评分；报告需解释每个 4 分所据的两个机位/状态，并列 47 项真实差异。旧 N04/N05/N07/N08 结论只在依赖哈希不变时复用，变了就复核。新候选必须重新计算 manifest/ZIP 哈希与包内外一致性。
5. `producer_review.py check` 达到 `ready_for_final_review=true` 且没有 N01/N02/N03/N09 未解问题后才提交集中独立审核。独立报告仍决定最终通过；制作侧不得自签。若再次退回，保留本候选，按共享原因开启下一候选。
