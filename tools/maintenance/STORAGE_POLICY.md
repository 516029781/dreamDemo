# 鼠鼠项目空间与产物淘汰规则

当前有效口径：**项目目录（含 `.git` 和项目内工具）控制在 15 GiB 内，12 GiB 预警**。执行前先运行 `storage_report.py`，按字节统计；“Git 已上传”不等于本地文件可直接删除，也不等于 Git LFS 临时文件安全。

2026-10-27 起采用**代码专用 Git**：Git 跟踪脚本、场景/工程配置、必要 `.meta`、设计规范、审核规则与小型 manifest；原生美术、参考图、导出资源、字体、视频和大型证据按用户选择留在本地素材目录，用路径/哈希清单校验。**当前没有异地素材备份**，GitHub 只保存代码，不能单独还原完整游戏。旧 Git 历史已从项目目录移出，旧历史备份的清理因自动审批 `blocked by policy` 尚未完成；不得绕过该拒绝。

执行入口：每轮开始/结束、每次预计新增 ≥50 MiB 的完整构建/导出/审阅包前，运行 `tools/workflow.py storage --planned-growth-mib <预计值> --enforce`。预检写 `delivery/workflow/STORAGE_STATUS.json`；预计总量超过 15 GiB 时暂停新的大产物生成，继续源文件返修、局部验证与容量恢复。`workflow.py run` 执行大命令必须带相同的 `--planned-growth-mib`，预检失败不启动该命令。摘要会显示最近预检状态，超过 24 小时须重测。检查本身不会删除文件。

## 保留优先级

| 等级 | 内容 | 淘汰条件 |
|---|---|---|
| 永久 | 当前项目代码、规范、工作流工具、地图可编辑 `.blend`/SVG/布局 JSON、角色原生源、经确认的素材来源与许可记录 | 只有明确替代/迁移并验证后才移除，不因体积超标自动删除 |
| 当前候选 | `candidate_n5` 正在编辑的源、真实构建、正式截图、Q/绑定、原始日志、manifest；本轮依赖的 n4 基线源/报告 | 当前制作与独立审核结束前只读保护；不得按日期自动淘汰 |
| 历史审核 | 已冻结候选的报告、最终评分、源/构建清单、关键前后图、SHA、独立结论 | 若要释放大包，先确认至少一份可恢复的远端或独立归档，保留索引与校验；不能只凭 Git commit 存在而删除未跟踪证据 |
| 可重建 | Cocos `library/temp/build`、工具下载缓存、旧候选非正式预览、重复录屏/ZIP、旧 stdout/stderr 副本、已失效的临时导出 | 确认不被当前工作包/正在运行的进程引用，再按候选和 run_id 成组清理；记录路径、大小与原因 |
| 旧 Git/LFS 历史备份 | 项目外旧仓库备份 | 删除曾被自动审批拒绝，保持原状并单独统计，不能改用其他命令绕过 |

## 每轮执行

### 候选版本保留窗口

以 `candidate_nX` 为单位滚动保留**最近 2 个候选版本**的可复查结果；当前制作中的版本始终计入窗口。例如 n5 制作期间保留 n4、n5，n3 不再常驻。退出窗口前检查当前构建是否真实读取旧版源、当前证据是否引用旧版路径，并保留必要报告/索引。旧版本若仍是实际输入，先将所需母版迁入共享源并复验；不能只按候选号机械删除。用户已明确不再查看 n3 画面结果，n3 大型工作副本可清退，但审计结论与历史 Git 处置分别记录。

每版的最小保留集合：可编辑原生源、运行所需项目源、最终 manifest 与 SHA、正式截图/行为证据、制作自评及独立审核结论、关键返修日志。构建缓存、临时预览、重复导出和过程 ZIP 按上述淘汰条件处理。相同字节的 GLB 只设一个规范导出源，运行时副本由构建步骤复制；切换前须验证构建与冻结包的路径约束。项目空间审计分别报告工作树、新 `.git` 和项目外旧历史备份。

每轮制作前先标记产物类别：`可复用原生母版`、`运行时导出`、`审核证据`、`可重建缓存`、`过渡试件`。下张地图优先复用组件母版与生成工具，不把旧地图整体 GLB 当通用素材；证据按候选可追溯保存，缓存不进入 Git。n5 的实测分类与具体复用办法见 `planning/performance/ARTIFACT_REUSE_AND_STORAGE.md`。

1. 制作开始：基线清单列出本轮会消费的源与旧候选证据。每个 run_id 写独立输出目录，日志和源分开；默认输出不允许覆盖前轮。
2. 局部返修：只留被采用的源试件、失败原因和一组可复查的前后图；无效的大图/GLB 草稿可在汇总 SHA 与反例后清理，但不能删当前候选正式证据。
3. 候选冻结：保留一个最终源包及其 manifest/包外 SHA；草稿 ZIP 不加入 Git。Git 远端只放代码、配置、场景结构、必要 `.meta` 与规范；原生美术和大型证据按本地素材清单管理。重复导出和构建不因“有 Git”而永久存储。
4. 独立审核通过后：将旧候选分为“保留的审核档案”与“可重建草稿”。至少保留最终候选和上一个失败候选的问题证据；更早大包先核实本地归档及引用关系，再按用户确定的保留窗口处理。当前没有异地素材备份，不能声称可异地恢复。`knowledge/CASEBOOK.md` 引用仍需可追到保留的报告/图/hash。
5. 每次清理前后用同一脚本报告总量、目录差值、保留项、删除项和预计重建成本。清理不改任务账本的通过状态；当前代码专用 `.git` 不使用 LFS，旧 LFS 历史位于项目外备份，且其删除曾被自动审批拒绝。

## 容量阈值

- **12 GiB 预警**：停止生成重复全量预览与草稿 ZIP，列出前 20 大目录；清理已确认可重建的旧输出。
- **15 GiB 上限**：不删除当前原生源或冻结证据来凑数；先排查历史构建、下载缓存和重复交付包。若仍无法下降，记录超额原因并将体积大的工具或历史归档迁出项目，修正使用路径后验收。
- 所有自动淘汰程序默认 dry-run。删除前检查规范化绝对路径仍在指定目录内，拒绝符号链接/重解析点、拒绝 `.git/objects`、当前候选、未核验的审核包。

当前项目仍在制作 `candidate_n5`，不能因清理空间覆盖它的源、构建或日志。
