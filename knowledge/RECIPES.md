# 可复用操作用例

更新：2026-10-26。以下是执行步骤和检查点；阈值、角色源、候选号均从有效合同和当前工作包读取。每条都需要实际证据，不得照抄“通过”结论。

## R01：修一个 ENV/UI/MIX 视觉缺陷

**适用范围**：同一个共享母版造成多张画面失分，如 n4 的树冠、铺地、对白或融合问题。**状态**：n5 推荐流程，尚未以 n5 实测证明提速。来源：`art_review/reports/candidate_n4_provisional_20261026/REPORT.md` 第 2/3 节、`planning/performance/N5_EXECUTION_DESIGN_AND_GAP_AUDIT.md` 第 1/2 节。

1. 取上个候选和当前候选的同机位原图，另列 P1 风格参考原帧；P1 与本地图不是同一场景/机位。只列出可见差距及其 rubric 维度，记录原图路径/hash。
2. 在候选 `performance/decisions.jsonl` 写：共享原因假设、将改的 `.blend`/SVG/材质母版、预期可见变化、反例区域、最小预览。
3. 修改原生源并做单体或固定相机预览。结果记为 `improved/unchanged/worse`，保留修改前后图/hash。无可见改善则换原因假设，不立刻做全量 Cocos 构建。
4. 局部成立后再定向构建、真实 canvas 采集和受影响 Q；相机/共享光/字体等全局变化扩大失效集合。正式冻结仍完整采集和检查。
5. 换审查视角看**未修改**区域、对白/暂停/竖屏等邻接状态；逐维重评，记录新缺陷和成本变化。达不到标准继续修原生源。

**不可套用**：只靠 Blender 渲染图判断 Cocos 最终材质；修改评分文字或沿用旧截图声称改善；为达到运行次数目标放弃返修。

树、铺地、材质/光、对白和融合的**具体原生源修改及失败替代方法**见 `knowledge/N5_VISUAL_PRODUCTION_PLAYBOOK.md`。本条只保留通用批次循环。

## R02：非出生点暂停/恢复行为回归

**适用范围**：移动、暂停、触控、横竖屏状态逻辑。**状态**：n3 制作侧有定向复验，后续候选仍待同源复核。来源：`art_review/reports/independent_20261025_candidate_n2/REPORT.md` 的 N09、`delivery/next_cycle/n3/T5/q04_behavior_moved.json` 和单独的 `q09_viewports.json`。

1. 用真实键盘和触控分别先移动到非初始点，记录玩家世界坐标、相机目标和任务状态。
2. 暂停后输入应锁定，位移为 0；恢复时不施加新移动输入，玩家和相机位移仍为 0，任务状态保持；恢复后新输入应再次移动。
3. 在已移动状态转竖屏再返回横屏，重查坐标、相机、任务和输入解锁；另用真实 viewport/canvas 采集证明竖屏尺寸与提示状态。不要直接 setter 到目标坐标冒充真实移动。
4. 把原始行为 JSON 与**另行记录的** build report/build_id、相关截图和绑定交给 Q04/Q09，核它们来自同一次构建；若状态逻辑或构建改变则重测。单个行为 JSON 没有 build_id 时，必须补同源绑定证据，不得自行补写旧文件。

**已观察结果**：n3 Q04 JSON 中键盘/触控恢复位移为 0，恢复后新输入位移分别约 1.05 m/1.80 m。该 JSON 没有 `build_id`，其 `portrait_canvas` 为 1280×720，不能单独作为 Q09 竖屏画布证据；另有 `delivery/next_cycle/n3/T5/q09_viewports.json` 和 `q09_portrait_720x1280.png` 记录了 720×1280 采集，使用时仍需核同源绑定。这些只说明 n3 那次制作侧测试，不能直接证明 n5 或微信真机。

## R03：冻结候选的同源证据链

**适用范围**：正式构建、Q、截图、源包和 manifest。**状态**：n4 已知错误的修复配方，n5 尚需执行验证。来源：n4 预审报告 P0-1～P0-3 与 n5 执行设计第 5 节。

1. 锁定可编辑源、截图、Q、评分与日志的输入；用显式 `candidate_id`、`build_report_path`、`build_id`，不按目录时间猜“最新”。
2. 先生成源 ZIP 并核 CRC/文件/重复项及 SHA；manifest 再引用该 ZIP 的 SHA。若还有包含 manifest 的外层审阅 ZIP，其 SHA 放包外。
3. Q02 的**候选对照图**、每条候选 Q、三张正式截图、绑定必须与当前磁盘 hash 和同一个正式 build_id 一致；P1 参考原图仅核其自身来源/hash，不属于游戏构建。任何必需文件变化使相应证据失效，重新采集/打包，不手工改 JSON hash 掩盖漂移。
4. 用 n4 三类已知坏样本做**只读负例**：ZIP SHA、Q02 图 SHA、build_id 错配均应被拒绝。保存实际命令/退出码和结果；最终完整候选再跑当前检查器。

**不可套用**：把 checker 结构通过当成审美通过；改冻结 n4 包来“修复”历史。
