# 可复用的静态地图美术制作流程

更新：2026-11-01。范围：把固定视角的 Blender 环境图制作方法迁移到另一张地图。本文复用**流程和诊断方法**，不复用 P1 秋日地图的造型、比例、相机、色板、评分锚点或世界坐标。

## 当前项目的物件密度偏好

用户明确要求：后续产物默认避免**密集树叶和草丛**，优先使用**体量较大的箱体、设备和结构物，表面细节克制**。这是项目级制作偏好，不是所有地图的强制规则；每张地图须在 `MAP_BRIEF.md` 明确记录自己的植被策略。

- 先用少数大型、轮廓清楚的物件建立画面层次；物件必须有场景用途和落脚/连接关系，不能用大方盒随机填空。
- 默认避免大量叶片、草卡、微小枝条、碎石/碎装饰重复实例化。若该地图 brief 要求植被，须给出参考依据与代表资产验证，再决定形态与密度。
- 箱体只做识别用途所需的接缝、开口或面板；没有证据支持的铆钉、磨损、线缆和标签不添加。先定大轮廓和明暗，再决定是否需要局部细节。
- 这是一条项目制作偏好，不是“低多边形/盒子风格”的万能模板。若某张地图的明确目标要求密集植被，先在工作单中指出与本偏好的冲突及评分影响，不得静默回到堆密度做法。

**业务专属边界的写法：**植被是否出现、以何种语言出现，由各业务 brief 与业务包决定；本文件不替任何业务规定“有/无植被”。P1 的当前政策与历史变更见 `knowledge/business/p1_autumn_static/BUSINESS_PROFILE.md`，不在通用方法里复制。

## 先划清哪些可以复用

| 可复用的制作规则 | 每张地图必须重新定义 |
|---|---|
| 候选隔离、版本身份、源/图哈希绑定、重开复现 | 该地图的参考图、镜头、可观察区与遮挡 |
| 先空间灰模、后代表资产、再组合图、最后完整画面 | 地形拓扑、层级、高差、路线和场所功能 |
| 一次验证一个主假设；从像素/对象所在处理层找根因 | 物件清单、物件用途、比例、数量、位置与连接 |
| 先做代表性小样，通过后再批量复制 | 地图专属材质、色彩、光照和雾参数 |
| 低成本诊断、局部验证、稳定后才出正式图 | 参考适配的六维权重、区域指标和硬门槛 |
| 保留失败反例并记录有效范围，不把推测写成事实 | 该地图的版权/素材来源与可发布边界 |

**规则：迁移方法，不迁移答案。** 新地图不得因为 P1 使用暖色石板、秋草、水池或某种机位，就把这些设为新地图默认方案。任何来自其他游戏或开源资源的数据都要和视觉参考分开标注。

## 新地图的执行顺序

### M0 建立地图专属任务卡

开工前先写一页 `MAP_BRIEF.md`：地图名与目标用途、唯一/分层参考及来源、固定镜头、要呈现的区域、禁止内容、最终交付格式、当前评分门槛。把资料分为 `visual_reference`、`structural_reference`、`tooling_reference`；结构数据不能冒充美术图，工具文档不能冒充制作规格。

并建立机器可读的 `ACTIVE_MAP.json`，至少包含：

```json
{
  "map_id": "unique-map-id",
  "status": "briefing | blockout | production | review | complete",
  "reference": [{"path": "...", "sha256": "...", "role": "visual_reference"}],
  "active_candidate": {"path": "...", "scene_sha256": "...", "image_path": "...", "image_sha256": "..."},
  "quality_status": "unverified",
  "active_work_order": "...",
  "superseded_plans": []
}
```

狀態檔內的場景和圖片哈希分别确认文件身份；只有记录了渲染命令、源哈希、图哈希和复现结果，才能声明源图同源。不要按文件修改时间自动选“最新版本”。

### M1 建立可比较的参考目标

锁定参考图 SHA 和相机信息。标出：画面锚点、空间分区、遮挡/不可观察区域、主要材质区域和远近层次。参考有 UI/人物而候选无 UI 时，先排除不可比部分；跨相机时按语义区域对照，不能机械比较同一像素坐标。

指标没有可复核的计算方法、容差依据和人工验证时标成 `diagnostic_only`。全图亮度、HSV、边缘密度不能单独成为美术门槛，也不能直接触发全局调色或几何修改。目标画风与评分只维护在该地图的视觉标准，不在通用流程里复制一套数值。

### M2 先证明空间成立

用低成本灰模回答：场景有哪些层级，地面是否连续，主要物件落在哪里，结构如何支撑/连接，镜头如何读出主次。建立对象/区域表，关键资产标注用途、承托面、依附对象、遮挡关系和画面区域。检查接地、穿插、楼梯落脚、栏杆开口与悬空；不做玩法或真实通行承诺，除非任务明确要求。

灰模未通过时不要做高精度材质、植被批量复制或正式大图。构图与镜头锁定后，改变它们必须记录新基线并重检整张画面。

### M3 小样先行，再扩资产

对每种高影响资产先做最小代表样：一组主设施、一类主要地形/铺装；只有该地图 brief 明确需要植物时才做一个低密度代表样。必须在目标相机、光线和最终画幅比例下看全图缩略与细节局部；小样通过轮廓、材质身份、比例和画风后才批量制作。当前项目默认优先制作大箱体/设施体量，禁止先做密集叶草资产再想办法塞入地图。

复制前检查 Blender 的 linked mesh/material 是否共享数据；编辑共享材质会污染整组对象时，显式建立独立数据或统一设计修改。新增/重排对象后做增量接地和外链检查，避免问题拖到灯光阶段才发现。

### M4 根因定位后再修改

遇到异常像素或物件，按层排查：

1. 命中哪个对象/几何面，是否被遮挡或存在隐藏对象？
2. 材质节点、贴图、UV/透明度是否产生该效果？
3. 灯光、World、阴影、雾是否改变它？
4. 合成器、色彩管理、景深、曝光是否在最后改变像素？

选择适合的诊断证据：对象/材质 ID、射线定位、render pass、局部消融或分组二分隐藏。每种工具都有边界：射线需考虑隐藏和透明物体；ID pass 需验证曝光/色彩变换下是否正确解码；hide-render 的影响需实际渲图确认。根因未定位前只做诊断，不同时调几种材质和灯光。

### M5 分档渲染与单假设返修

| 档位 | 用途 | 退出条件 |
|---|---|---|
| 不渲染 | 文件、参数、对象、外链、节点检查 | 已排除机械原因 |
| 低采样局部/半分辨率 | 验证单个材质、光照、透明、接缝或遮挡假设 | 目标局部有可见改善，邻区无明显回退 |
| 同机位全图中档 | 检查构图、物件组合和其他区域回归 | 主要目标及全图均成立 |
| 正式分辨率/采样 | 最终候选交付 | 空间、母版和色光都稳定后才执行 |

每批只提出一个主要可证伪假设；保存参数、命令/退出码、前后图、耗时与 SHA，结论记 `improved/unchanged/worse`。同一方法两次无改善，换诊断层或资产方法继续，不将失败次数当任务完成。当前没有全流程墙钟数据时，不承诺固定节时百分比；逐轮统计后再比较。

### M6 评审与返修闭环

每张地图必须使用它自己的视觉标准。先由制作侧列扣分原因和要改的源对象；问题项写“参考可见特征、当前反例位置、原因假设、改动位置/参数、验证方法”。当前 P1 由制作模型连续自评返修，评分后再逐维找反例并说明保分/扣分；质量 gate 核对机械证据，不要求其他模型独立终审。该反证步骤是偏差控制提案，不等于独立视觉认证。任何最终图变化后，旧自评不得沿用。新地图是否需要额外独立评审由其 brief 定义。

门槛按该地图项目当前批准标准执行。没有经最终验收的地图，不记录成“成功美术案例”；但可以把经复测的通用技术方法记为“已验证流程经验”，并限定适用范围。

### M7 版本、证据与清理

- 每次候选独立存放；源、最终图、参考、评分和交付报告绑定完整 SHA256。
- 交付前确认所有清单文件存在、哈希相符、尺寸和引用正确；隔离目录重开 Blender 并复现渲染，记录 Blender 版本、命令、退出码、源/图 SHA 与允许的采样差异。
- 旧证据保留作历史，标清它对应的确切图像和源；新版本不能覆盖旧报告来让哈希看似匹配。
- 清理前从 manifest 生成保留集并做 dry-run；不按含糊文件名或“旧版本”标签删除唯一证据。

## 经验库的状态标签

| 标签 | 使用条件 |
|---|---|
| `observed` | 某候选日志里观察到，尚未重复复核；只能作线索 |
| `reproduced` | 独立复测再次得到相同现象，注明 Blender 版本与条件 |
| `reusable` | 在不同资产或不同地图中复用成功，并写出适用边界 |
| `proposed` | 由复盘提出、尚无足够复测证据的流程改进；可在新图试行，不宣称已证明节时 |
| `deprecated` | 已被证伪或过时，保留原因防止重复尝试 |
| `map_specific` | 仅适用于特定地图、参考或相机参数 |

不得把“V25–V27 的最终画面已成功”写入案例库：当前图尚未绑定有效评审。以下过程经验可以带状态迁移：

| 经验 | 当前标签 | 来源与边界 |
|---|---|---|
| 远景异常先追到合成器/雾层，再决定改贴图或材质 | `observed` | V25 多轮返修才定位 Mist 参数；需在其他场景复测后升 `reusable` |
| 植被和设备先做小样再批量复制 | `observed` | V25–V27 有小样、换法和批量回滚记录；可降低风险的假设尚未跨地图测时验证，不能保证美术通过 |
| Blender linked duplicate 的共享 mesh/material 可能导致整组被污染 | `observed` | V25 日志中出现一次共享材质污染；复制前检查数据共享，更多场景复现后再升状态 |
| 参考图有 UI/角色时，不把全图颜色统计直接作用于无 UI 候选 | `observed` | 当前 P1 参考与静态图口径审计；方法有待新项目重复应用，具体 mask 每图重做 |
| 清理前用 manifest 保留集核验 | `proposed` | 由 V25 113 张诊断图误删事故提出；这是待落实的保全规则，不代表清理脚本已实现 |
| 某套手绘冠/草卡画风可直接复用到所有地图 | `deprecated` | 不成立；美术语言和植被类型需按新地图参考重建 |

## 新地图项目配置模板

复制以下字段到新地图的 `MAP_BRIEF.md`，所有 `[待定义]` 由新参考资料决定，不得从 P1 自动填值：

```text
地图 ID / 名称：[待定义]
目标类型、平台与最终镜头：[待定义]
视觉参考（路径、来源、SHA、用途）：[待定义]
结构参考（路径/数据、来源、用途）：[待定义]
画面锚点 / 遮挡区 / 可观察区域：[待标注]
场景区域与高低层级：[待定义]
物件组（用途、承托、连接、区域）：[待定义]
密度偏好/允许的细节级别：[按该地图用户要求；默认避免密集植物；当前 P1 为零植被、大体块、少细节]
目标色彩/材质/光照：[从本地图视觉参考提取]
禁止迁移的外部素材或风格：[待定义]
当前评分标准与硬门槛（唯一文件）：[待定义]
候选命名与 manifest 路径：[待定义]
完成交付：[源、图、证据、报告]
```

## 与 P1 当前工作的关系

P1 当前执行入口仍见 `planning/art/ACTIVE_STATIC_ART.json`；P1 的85分标准、秋日画风与 `t084s.jpg` 只约束 P1。当前 `v25/renders/final_v27.png` 尚无针对当前图 SHA 的有效评分，不能作为其他地图的已验收视觉样板。可复用的是本文件中明确标注的流程方法及风险教训。开启另一张图时，先新建该地图的 brief、参考 profile、评分标准和 active state；不要改变 P1 的锁定参考，也不要把两个地图的状态混在一份 manifest。
