# 代码专用 Git 与美术素材保存

更新：2026-10-27。用户要求 Git 仅提交关键代码，原生美术文件与导出/证据大包留在 Git 外。**不要把“不入 Git”理解成“可删除美术源”。** 游戏运行和后续地图复用仍依赖这些本地文件。

| 位置 | 保存内容 | 恢复责任 |
|---|---|---|
| Git | `tools` 脚本、游戏逻辑 `.ts`、场景 `.scene`、配置和必要 `.meta`、设计规范、审核规则、少量文本 manifest | 代码仓库与提交历史 |
| 本地素材目录 | n4/n5 的 `.blend`、GLB、纹理、字体、角色原始资源、P1 参考与正式审核图 | 独立素材备份；用 `LOCAL_ASSET_MANIFEST.json` 中的路径/字节/SHA-256 校验 |
| 可重建目录 | Cocos `build/library/temp`、隔离探针、下载缓存和草稿输出 | 构建脚本，按空间规则淘汰 |

`.gitignore` 从本轮起阻止新的大媒体文件加入 Git。已有被跟踪的二进制不会因 `.gitignore` 自动从索引或历史消失。`tools/maintenance/prepare_code_only_snapshot.py` 会在 `.tooling` 下创建**隔离的新 Git 仓库**，只复制选中的文本文件，并生成本地素材哈希清单；它不更换当前 `.git`、不删除源文件，也不配置远端。

## 切换前必须验证

1. 检查新仓库的文件清单，确认当前 n5 的游戏脚本、场景、构建/审核脚本和 `.meta` 均在其中；确认 `.blend`、模型、图片、字体、视频、ZIP 及日志均不在其中。
2. 把本地素材复制到独立于当前 Git 仓库的可恢复位置，按哈希清单抽验和全量校验；完成一次“代码快照 + 素材备份”的还原构建。没有这一步，代码仓库本身无法还原完整游戏。
3. 当前 `master` 比 `origin/master` 多 31 个本地提交，远端另有 1 个分叉提交。旧 Git 历史改写前，先决定旧历史是否还需远端归档，并验证远端备份/LFS 可恢复。不能将唯一的本地历史直接删掉后声称已经上传。
4. 以上通过后才将项目切到代码专用 Git，并重新统计项目目录和整个磁盘。移出项目的工具只影响项目目录大小；删除旧 `.git` 才会释放其本地占用。远端主分支的强制覆盖属于单独的发布操作，不由准备脚本执行。

当前工作区保留 n4/n5 两版产物。Git 只存代码后，版本化美术源由素材清单和独立备份承担；新候选制作时同步更新清单，不允许只留下最终 PNG/GLB 而丢失可编辑 `.blend`。

## 隔离快照实测

2026-10-27 准备了代码快照：约 **788 个文本/配置文件，7.0 MiB**，新 `.git` 约 **1.4 MiB**，且没有 Blender、GLB、图片、字体或 ZIP。清单记录 **502 个本地素材文件，合计约 1.05 GiB**；它只含路径/大小/SHA，不含素材字节。首版快照发现 `.gitignore` 的 `assets/` 意外屏蔽 `demo_n5/assets`，已改成只匹配项目根的 `/assets/`，重新生成并核实启动脚本、主场景和必要 `.meta` 都被跟踪。准备脚本现在会在提交前自行检查这些关键文件与禁入二进制。

这一结果说明旧历史在空间上确实可以省掉，但**尚未更换活跃仓库**：需要先选定素材独立备份，并验证“代码 + 素材”的还原路径。旧仓库存在未上传提交和远端分叉，不能仅用新的小 `.git` 目录覆盖它。
