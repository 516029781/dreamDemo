# 代码专用 Git 与美术素材保存

更新：2026-10-27。用户要求 Git 仅提交关键代码，原生美术文件与导出/证据大包留在 Git 外。**不要把“不入 Git”理解成“可删除美术源”。** 游戏运行和后续地图复用仍依赖这些本地文件。

| 位置 | 保存内容 | 恢复责任 |
|---|---|---|
| Git | `tools` 脚本、游戏逻辑 `.ts`、场景 `.scene`、配置和必要 `.meta`、设计规范、审核规则、少量文本 manifest | 代码仓库与提交历史 |
| 本地素材目录 | n4/n5 的 `.blend`、GLB、纹理、字体、角色原始资源、P1 参考与正式审核图 | 用户选择仅本地保留；用 `LOCAL_ASSET_MANIFEST.json` 中的路径/字节/SHA-256 校验，当前不能异地恢复 |
| 可重建目录 | Cocos `build/library/temp`、隔离探针、下载缓存和草稿输出 | 构建脚本，按空间规则淘汰 |

`.gitignore` 从本轮起阻止新的大媒体文件加入 Git。已有被跟踪的二进制不会因 `.gitignore` 自动从索引或历史消失。`tools/maintenance/prepare_code_only_snapshot.py` 会在 `.tooling` 下创建**隔离的新 Git 仓库**，只复制选中的文本文件，并生成本地素材哈希清单；它不更换当前 `.git`、不删除源文件，也不配置远端。

## 切换验收记录

1. 新仓库清单核对通过：当前 n5 游戏脚本、场景、构建/审核脚本和必要 `.meta` 均被跟踪；`.blend`、模型、图片、字体、视频、ZIP 及日志未被跟踪。
2. 用户选择素材仅在本地保存；按清单对 502 个文件完成全量 SHA-256 校验。未进行异地素材恢复演练，因此代码仓库本身不能还原完整游戏。
3. 旧 Git 历史移到项目外备份。远端 `master` 经用户授权改写为代码快照，预览分支删除；旧历史备份的删除被自动审批拒绝，仍占用本机磁盘。
4. 项目切换后复核 Git 完整性、工作树状态和容量门禁。后续候选必须更新本地素材清单，并验证美术源和运行时导出的对应关系。

当前工作区保留 n4/n5 两版产物。版本化美术源由本地文件与素材清单承担；新候选制作时同步更新清单，不允许只留下最终 PNG/GLB 而丢失可编辑 `.blend`。

这一结果说明旧历史在空间上确实可以省掉。切换前已核实代码分支和本地素材清单；用户选择素材继续仅在本地保存。完整游戏的异地恢复能力因此仍未建立。

代码快照先在 GitHub 预览分支验证。用户随后明确授权替换远端 `master`：用精确 `--force-with-lease` 从 `bf7ce94` 更新至代码快照 `ad92d9a`，远端核对通过；预览分支已移除，当前只有 `master` 指向代码历史。GitHub 可能仍在其内部保留不可从分支访问的旧对象，不能把改写分支等同于服务端物理清除。**远端不备份清单列出的 502 个美术文件。**
