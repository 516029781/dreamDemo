## 可复用的内容

1. **可编辑资产母版**：`ENV001` 石铺地、`ENV002` 路缘、`ENV003` 低墙、`ENV004` 栏杆、`ENV005` 台阶、`ENV006` 树、`ENV007/008` 花坛，以及 `PROP001–006` 道具的 `.blend`。复用时改尺寸、材质和损耗，不把当前庭院布局照搬到新地图。
2. **美术规则与生成方法**：`art/candidates/candidate_n5/source/materials`、`textures`、灯光/相机配置、UI 的 SVG/原生层和绘制规范。下张地图先套规则做一个局部样板，仍要与新参考画面复核。
3. **工程与校验工具**：`demo_n5` 的场景加载、角色控制、UI 状态和 `tools` 下的构建、包体、行为与审核脚本。复制工程时更换地图 ID、场景资源与证据路径；不得沿用 n5 的冻结 hash 或审核结论。
4. **角色源**：仅在现行角色来源合同及许可允许的范围内复用锁定源和动作；不把旧导出截图当成可编辑角色源。

## 后续候选的执行约束

- 开始前列出“沿用母版 / 改造母版 / 新制资产”，记录唯一规范源与导出路径。大于 50 MiB 的产物先运行 `tools/workflow.py storage --planned-growth-mib <预计值> --enforce`。
- 一个资产只认一份可编辑母版；运行时导出由脚本复制。正式证据仍按候选、run_id 和 hash 独立保存，避免跨候选覆盖。
- 预览失败时先留一张反例和失败原因；无效的大型 GLB、重复帧及草稿 ZIP 不进入长期保留。当前候选与冻结包不得自动清理。
- 每轮结束统计新增字节和最大 20 个文件，保留最近 2 个候选的可复查结果；当前 n5 的窗口为 n4/n5。旧版退出前确认当前构建没有真实读取它，并保留必要审计索引。用户明确不再查看 n3 画面结果，n3 大型工作副本可清退；删除工作副本并不等于删除 Git/LFS 历史。
- **微信小游戏发布包单独设门禁**：原生 `.blend`、审核图和 Git 历史不进入发布包。微信构建需测主包、分包与远程资源，不能用工作区 12 GiB 门槛替代平台包体验收。

## 2026-10-27 两版清退记录与剩余大头

用户将常驻窗口改为 n4/n5。已从当前工作树移除 n3 的美术候选、Demo 与 `delivery/next_cycle/n3`，约 **0.265 GiB**；另外移除 n4 之前的 10 份旧源码/审阅 ZIP（含 n5 中间版 v8），合计 **623.6 MiB / 0.609 GiB**。n4 的 v7 与 n5 的 v9 源包保留。旧报告与 SHA 记录仍留作索引；Git 历史暂未裁剪，删除文件的提交可恢复这些内容。

清退后必须注意两件事：

- `tools/blender_n5/build_map001.py` 的 `append_bench()` 实际从 `tools/blender_n5/courtyard_lib.py` 定义的 **n5 `SRC_PROP`** 读取长椅母版，但写入 Blender 自定义属性和记录的部分来源字符串仍指向 `candidate_n3`。这是遗留来源标记；n5 冻结证据不能为了清盘而改写。下个新候选应统一改为真实的规范源路径，再生成和验证新证据。
- 清退大量 LFS 跟踪文件后，桌面 Git/LFS 状态扫描曾使 `.git/lfs/tmp` 增至约 **1.38 GiB**。它不是保留版本资产，不得将其计作成功压缩；先检查 Git/LFS 进程和远端状态。此前自动审批拒绝直接删除该临时区，不能换命令绕过。

**为何两版仍远大于 2 × 1.24 GiB：**项目内 Cocos 编辑器约 **5.45 GiB**、其他 Blender/Python 工具约 **1.37 GiB**、Git 正式 LFS 对象约 **3.12 GiB**、Git 普通历史约 **1.16 GiB**，另有独立探针约 **0.52 GiB**。两版本身不是主要大头。

若要把**项目目录**压到约 7–8 GiB，必须组合：核验后把 Cocos 编辑器移出项目（项目账面减约 5.45 GiB，但整盘不节省）、处理隔离探针（约 0.52 GiB）、安全同步全部本地提交后创建只含 n4/n5 与规范源的新 Git 快照（历史 LFS 可能节省约 1–2 GiB，实际以重建后扫描为准）。本地 `master` 与 `origin/master` 有分叉且多项提交尚未上传；远端/LFS 未经恢复验证前不得改写现有 Git 历史或直接删除 `.git` 对象。
