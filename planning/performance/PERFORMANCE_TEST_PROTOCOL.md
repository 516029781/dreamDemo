## 4. 计时设计

### 4.1 两种计时，分开报告

1. **工具重放计时**：固定修改、固定命令和输出范围，测导出/构建/采集等工具路径。可复现，但不证明模型理解和试错耗时减少。
2. **端到端模型执行计时**：从模型收到相同任务包到提交可审结果，包含阅读、修改、重试和工具往返。若要证明模型端到端提速，需要同模型版本/推理设置、等价初始上下文的隔离会话；A/B互不读取对方答案。无法控制就标观察性数据，不作因果证明。不得擅自创建/发送其他聊天，由用户提供会话或明确授权后协调。

工具已运行但质量未达到相同要求时不算可审完成；返修成本纳入。达到运行限制就记录未完成，不给失败任务一个虚假的低耗时。

### 4.2 冷/热和重复次数

- 每个T任务：A/B各1次冷运行，加各3次热运行。冷仅指本试点应用/导出缓存为空、相关进程关闭；不清OS缓存，不删全局工具或用户缓存。
- 热运行使用同样的预热策略。每次计时前恢复相同修改前状态，再应用同一变更；保留允许的依赖缓存。不能把“没有任何变化的重复运行”冒充有修改的热迭代。
- 单独用N01测试无变化缓存命中。重复操作宜自动重放，不要求模型人工重做整套创作四遍。
- A/B执行顺序交替，记录顺序、后台负载和异常。禁止一边运行另一边争抢资源。
- 3次热运行取中位数，并保留全部原值、最小/最大；样本小，不宣称统计显著性。一次试点只说明这些测试任务。
- 若首次冷运行已显示方案不可靠或代价明显过高，停止该方案，保留失败证据，不继续无收益重跑；报告覆盖不足。

### 4.3 字段与公式

events.jsonl每个阶段至少记录：run_id、case_id、variant(A/B)、temperature、repeat、stage、UTC起止、单调计时duration_ms、输入/配置hash、输出hash、cache_hit、exit_code、status及日志路径。

端到端墙钟以整轮起止为准；并行阶段时长不得相加冒充墙钟。外部审核等待与其他不可归因间隔分列，无法归因就写unknown，不把工具间隔称为模型推理耗时。

- 单项热耗时：该项3次有效完成记录的中位数。
- 主要比例R：T01—T03的B热中位数之和 / 对应A之和；减少比例=1−R。另报每项，防止总数掩盖局部倒退。
- T04候选批处理单列，不混入常规任务总比例；不同工作负载不能重复加权。
- 首次采用成本：B完成相同任务的实际耗时＋优化开发/配置/计时工具成本；实验对照、重复测量成本另外完整披露。
- 原审核等待、优化后审核等待和含等待总交付时间另外展示。

没有可重跑A或可靠旧trace时，仅提交B耗时，结论必须写“缺少有效对照，不能证明50%/70%”。历史构建日志的7分钟不能当作旧完整开发耗时。

## 5. 缓存与失败负例（隔离副本）

| ID | 操作 | 必须观察到的结果 |
|---|---|---|
| N01 | 同一不可变输入重新执行 | 合理命中缓存，产物hash和证据引用可查；正式要求的检查不能静默丢失 |
| N02 | 改一个局部素材 | 该节点及下游失效，无关节点可复用；新截图绑定新输出 |
| N03 | 改共享材质/字体/相机之一 | 所有实际受影响节点/截图/相关审核失效；不只看修改文件名 |
| N04 | 在副本使一个必需源缺失，并保留上次成功输出 | 当前节点失败，下游不冒读旧输出，成功指针不前移，无依赖任务可继续 |
| N05 | 给构建日志解析器输入同时含失败事件与Finished的夹具 | 不误报成功；记录失败事件。仅验证解析器时明确标单元范围，不能说已覆盖真实集成失败 |
| N06 | 在副本中混入另一revision的截图或配置 | 绑定检查拒绝混版本，不允许只因文件存在就放行 |

共享依赖支持不全时判失败或未实现，不能把“没有检测到”写成“没有影响”。故障注入结束恢复副本并核对源；不触碰正式审核密钥或篡改历史报告。

## 7. 报告与判定

输出目录必须包含：

- README.md：本次范围、执行步骤、实际命令入口和未完成项。
- environment.json、inputs.json：环境、配置、依赖与源快照引用。
- events.jsonl、commands.txt、logs/：原始计时、实际命令与返回码。
- evidence/：A/B原尺寸图、候选联系表、功能结果及输出hash索引。
- summary.json：结构化计时、负例结果、质量状态、首次成本及结论。
- REPORT.md：用户可读报告，包含下表和缺陷修复建议。

结论必须区分：

- **通过50%目标**：T01—T03匹配覆盖、质量通过、必需负例通过且R<=0.5；说明这是工具重放还是模型端到端结果。
- **达到70%挑战目标**：同样条件且R<=0.3，仅适用于实测任务范围，不推广为完整游戏工期。
- **部分有效**：部分任务快，或整体不足目标；逐项保留有净收益措施，不隐藏慢项。
- **待独立审核**：速度有效，质量/放行仍待审。
- **无法判断**：对照缺失、范围不同、未完成、计时不可靠。
- **失败**：缓存错误、混版本、旧输出误放行、关键质量/行为退化等；即使更快也不能推广。

首次成本高于收益必须明说。不能从同一套固定修改的工具重放，推断后续模型在未知美术问题上的创作和判断也获得相同比例提速。
