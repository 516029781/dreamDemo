## 1. 先纠正目标判断：背景到底缺什么

P1 的远景依靠**深色秋叶、浅暖岸地、蓝青水面、被柔化的远处轮廓**组织空间。它不是一张完整可探索的背景地图。参考的左侧部分被游戏 UI 遮挡，只能对可见轮廓做要求；被遮挡区域可做符合相邻结构的原创延续，不能声称逐像素复原。

### 固定镜头下的质量分级

| 级别 | 按最终图判定的对象 | 制作要求与停止点 |
|---|---|---|
| A：主景与视觉焦点 | 前景台阶/栏杆、连续石板、主树枝干和冠缘、三座圆筒草池的根部与叶缘、中央设备、右侧圆塔等清楚可见的主物件 | 保留能被原尺寸局部看见的厚度、接缝、支撑、材质和植被层次；先修摆放再修局部画质。即使物体位于画面上方，只要轮廓醒目也属于 A。 |
| B：连接层 | 桥、近岸、左树下地被、前景土面及有助于解释空间的次要设施 | 结构和接地准确，轮廓自然；小细节只在固定机位可见时制作。左树下地被不能因被叫作“背景”就变成贴地色块。 |
| C：远景 | 蓝青水带、远岸、最远地形与树影 | 用可编辑的简化网格/2.5D 层完成形状、颜色、软边和遮挡；不做背面、看不见的建筑细节或高密度纹理。远景只需在最终画面上成立，无须具备近看资产精度。 |

先从固定相机做可见像素/焦点检查，再决定级别。以最终 1920×1078 图计，投影不足约 2 像素的孤立装饰优先省略，约 2–6 像素的装饰优先合并为轮廓；这是**省工启发式，不是评分阈值或 P1 原作参数**。细栏杆、连续接缝、成片细叶等虽单根很细，却共同决定轮廓、阴影或材质读感，不能按此规则逐根删除。镜外物件若投下可见阴影、参与反射或遮光也不能直接裁掉。大面积远处剪影即使纹理很软，形状错误仍要修。可见的前景接缝、草根和树枝在原尺寸裁切中检查，不能用半尺寸整图掩盖缺陷。

远景最低完成线是：参考中可见的冷色水带仍能读出；水与暖岸、暗秋叶及最远软轮廓形成四层；岸线自然但不过度加装饰；远景明暗/锐度弱于主景；没有明显大片平板、硬棕色山墙或等距复制树。满足该线且不触发全画面光色 `rework` 后即**停止加远景细节**，把剩余工时留给 A/B 区。简化远景不等于允许空白背景。

### 背景绘制方法

1. **先描图，再建模**：把 P1 与 I53 图统一到 1920×1078，标注可见的树冠、地被、暖岸、水面、远景剪影；单独保存 UI 遮挡 mask 和手工标注的不确定区域。先复核/复用 `reference_analysis/P1_REFERENCE_PROFILE.json`；`BG_TARGET.json` 只登记本轮的编辑对象、目标轮廓和深度选择，并引用 profile 的 SHA，不复制另一套锚点、ROI 或评分阈值。每个区域记录允许留空的负空间和可见遮挡关系；P1 标准中的矩形是近似位置，不自动当作精确分割边界。
   本轮读取确认：v08 profile 已有六锚点、颜色 ROI，且为 `evaluation_mode: manual_only`、`numeric_tolerance: null`，**尚无明确的遮挡 mask 记录**。P0 在新候选内补上参考 UI/角色/字幕的遮挡多边形或 mask 路径、尺寸、SHA 和标注来源；复用已核对的锚点，避免整套重做。参考 UI 遮住的区域不做相似度评分，但候选该区域仍须检查接地、材质与画面连贯性。补 mask 不等于完成自动视觉验收校准，模式继续保持 manual_only。
2. **反投影与落地**：水/岸的屏幕曲线按已选的物理高度与相机射线求世界坐标，树与地被按已有地面和根点定深度。先用 `world_to_camera_view` 复投影核对；若世界位置不合理，调整深度/高度，不能用悬空画片硬对齐。
3. **验证真实可见面积**：投影包围盒落在目标区不等于画面可见。I50 就落在画幅内却几乎无效果。用低分辨率平涂物件 ID/遮挡预览取得实际可见像素 mask，再人工检查其与目标轮廓的关系；不够可见就先改轮廓/遮挡关系，不运行正式 Cycles。ID 图只检查几何占位与遮挡，不判断光色、透光叶片的最终质感或景深；半透明/细叶边缘及背景柔化要回到材质预览核对。未校准的交集比例只能作诊断，不能自动判美术通过。
4. **分层上材质，提前锁景深**：沿用现有可编辑土、水、树与石材资产，维持暖岸/冷水/暗叶/浅石的色彩角色。P0 用低成本全图确定焦点、景深、曝光与主光，保证石板、草池和主设施在最终图中可辨；P2 通过远景造型和低对比材质形成柔软层次，不临时加大全局景深模糊。确需改焦点或光照时，返回整图校准并重验主景，不能继续沿用旧局部通过结论。轮廓与承托通过后再加粗糙度、低对比色差；不得靠全局调色或装饰掩盖结构问题。

只做一套固定的**全画面对照板**：P1 可见环境与候选统一画幅、裁切和参考遮挡 mask；v08/v09 的前后比较还须固定候选相机，不能声称知道参考截图的原始相机。先在板上按可见影响列出最多三个高优先级差距，再锁定 P1 主景和 P2 远景的目标轮廓；不要因为标题是背景方案，就让小面积远景缺陷压过前景石板、主树或草池。每层明确“保留/改动/不画”的对象和参考可见证据；没有轮廓依据的新增物件不进入构建。若编辑现有水岸网格仍不能形成目标曲线，备用做法是**带真实岸脚的可编辑 2.5D 远景剪影**；两种方法都失败时回查投影深度与遮挡，不继续叠加低矮土丘或同源树。

| 圆塔顶草 | 草包围盒局部越过冠沿约 0.17 m；草根起点与土顶均约 `z=3.73`。 | 这是可接受的叶尖外垂，不按“草出盆”误删。只检查根点是否在土床及外垂是否遮挡塔体轮廓。 |
| 叉车轮 | 四轮最低 `z≈0.033`，与地面 `z≈0.035` 接近。 | 当前接地基本正确，保持；不要把所有越界对象都当成错误重修。 |

正式开工后还要用同一套方法巡检：箱/桶与台面、栏杆立柱与平台、桥端与两岸、水边植物与土面、远处树根与地形、圆塔的墙脚与地面。审计结果分 `confirmed_error / acceptable_overhang / needs_visual_check`，只修有证据的项。

### 新增的项目级摆放检查（工程约束，不冒充 P1 原作参数）

- 种植组必须声明 `root_surface`、根点集合与父对象。根点在土面边界内，并在土面高度 `±0.05 m`；只允许叶尖/枝条越沿，不允许根茎整体漂移。
- 树根必须落在盆内土面，离土面边界至少 `0.10 m`；树干底部与盆土顶的高度差目标 `≤0.05 m`。树可以为构图略偏离盆中心，但偏心量须在 `BG_TARGET.json` 里标出，固定镜头能看出它确实种在盆里；不把“绝对居中”当作艺术目标。
- 梯、栏杆、桥、设备等硬物的承托/连接间隙目标 `≤0.05 m`；外观允许有设计缝，但须有明确连接件。轮胎接地目标误差 `≤0.05 m`。
- 这些检查先读场景世界坐标，再做固定镜头和侧视复核。数字是本项目的制作公差；若现有模型尺度要求调整，要记录原因，不能静默放宽以求通过。
- `0.05 m` 只是几何预检容差，不允许最终图出现可见悬空或穿模。用实际承托面高度和接触区域检查，不能拿全局地面高度或组包围盒代替；树根/土床不平时按局部表面求交。机械通过但原尺寸可见间隙时仍返修。

## 3. 把返修从几十轮压到少数有效批次

### 已看到的时间瓶颈

- 当前 v08 的历史目录有 **197 个文件、44 份 `.blend`，其中 `.blend` 约 3.23 GiB**。每次保存整场景增加 I/O 和人工辨认成本。
- I53 预览为 50% 画幅，`render_log.json` 记录纯渲染 **35.36 秒**，Blender 从启动到保存预览约 **89 秒**；余下约 54 秒花在场景生成、素材载入/编译和保存等环节。正式 1920×1078 图为 **205.02 秒**。这是当前样本，不是未来每轮的固定耗时。
- 保存的场景共有 728 个对象，其中 **181 个处于隐藏渲染状态**：旧程序树 62 个、已隐藏厂房 34 个、被圆塔取代的墙体组 51 个、其他 34 个。它们仍由当前脚本先生成再隐藏；先按代码段计时，若生成成本显著，就在 v09 的完整重建路径中跳过这些旧分支，不能直接删掉尚被别处引用的材质或锚点。
- I42 的塔最初几乎在画面外；I49/I50 的岸线修改几乎不可见；I52 的调色变化近乎零。这些轮次共同的问题是**源参数改了，但画面目标与可见面积没有先验证**。只缩短渲染时间不能消除错误判断。
- I53 的叶片 AO 与更复杂的场景可能增加全尺寸渲染成本；现有 I40 与 I53 完整场景不相同，暂不能把耗时增长归因给 AO。确认后只在相同场景做一次开/关对照，若视觉收益不足则撤回。
- 即使把 **53 次迭代都按目前约 89 秒/次** 粗估，预览合计约 79 分钟，只占用户所说 8 小时流程约 16%；各轮实际耗时不同，这不是已测得的总时长。因此只优化渲染器达不到“总耗时减半”。必须同时缩短选错方法、返工、重复汇报和寻找证据所花的时间，并在新周期分别计时。

### 构建策略：只改活动组，保留完整可复现源

v09 以 SHA 已锁定的 v08 `scene.blend` 为只读起点，登记基线和素材路径清单；默认直接只读加载受保护的 v08 基线，**不为每批复制基线和全部贴图**。用确定性的 `apply_v09.py` 只改本轮列明的摆放、主景母版和背景组，再保存 v09 `scene.blend`。这样参数试验无需每次从零生成全部 728 个对象。脚本启动时必须核对**基线 SHA 和预期对象清单**，始终从不可变基线读入，先写临时输出再替换 v09 工作场景；不得在已经打过补丁的场景上再次叠加位移。为对象补父级时保存其世界矩阵，先证明零位移重组不改变画面，再执行目标变换。最终包包含基线依赖声明、补丁脚本、可独立重开的最终 `.blend` 和实际使用的本地素材；最终 `.blend` 不依赖旧版本的临时路径。补丁复建需要的基线保留并禁止清理，若日后要删除 v08，先迁移此依赖并复测。

先对“零改动补丁”做一次加载/保存和固定镜头对照，记录新旧可见图是否一致以及实际耗时；确认 52 个外部图像路径在 v09 仍可解析。如果增量路径没有明显节省或破坏贴图/对象引用，就退回完整构建，并先为树、草、旧厂房等代码段加计时，再优化最慢的一段。无论采用哪条路径，背景轮廓验证先用廉价 ID/平涂图，正式 Cycles 只在结构检查通过后运行。

构建优化只做本轮能回本的部分：记录改造时间 `C`、每次构建节省 `s` 和预计剩余次数 `N`，仅在 `C < s × N` 且没有增加复现风险时继续扩展；单位统一为分钟。若搭增量框架本身比剩余渲染省下的时间多，就沿用现有构建脚本做最小修补。不在美术返修途中重写通用工具链。先记录一次空间占用，新增 ≥50 MiB 前按现行工作流容量预检；15 GiB 上限与 12 GiB 预警继续有效。素材只保留最终实际依赖，不另生成重复 ZIP 或整包副本。

Cycles 重新渲染的像素 SHA 可能跨进程微变。交付时应从**重开的最终 `scene.blend`** 生成唯一正式图，记录该次输出的真实 SHA、退出码与相机参数；门禁中的 `reproducibility.render_sha256` 绑定这次正式图。需要额外复渲检验时，另记录像素差和是否存在可见变化，不伪称第二次渲染必得相同 SHA，也不拿旧图填复现字段。

### 新的执行批次与停止条件

执行顺序为 **P0 整图校准 → P1 摆放及主景 → P2 远景收尾 → P3 正式验收**。P0 对应 G0 及复用候选的 G1 核对，P1/P2 对应 G1/G2，P3 对应 G3。先在低成本全图中确认灰度层次、暖石/暗叶/暗设施/冷水和远景软硬，再细修主景；不能等 P2 才第一次决定背景颜色或景深，否则会推翻 P1 的材质判断。

| 批次 | 一次完成的内容 | 先过的便宜检查 | 允许进入下一步的证据 |
|---|---|---|---|
| P0 目标与错误清单 | 固定 P1 mask、A/B/C 级目标轮廓和 I53 当前轮廓；冻结 v08，建立 v09；复用已有 profile，校准全图早期色块和软硬层级；确认最终评审通道可用 | 同画幅叠图 + 场景坐标审计 + 低成本全图/灰度检查 | 有明确的六锚点、主景局部、远景最小轮廓、空白/遮挡区及支持关系；最多列三个高影响差距；记录固定曝光、灯光和景深基线 |
| P1 摆放与主景质量 | 先分别修三盆细草茎、梯子、右前景草并机械核对，主树按土床复核结果决定是否移动；再按叠图修 A 级的石板/树/草池/设施中**仍可见的最高影响缺陷**，检查 B 级左树下地被及连接 | 世界坐标公差 + 25% 平涂支撑图；A 级使用原尺寸局部，B 级用同镜头中等预览 | 已确认摆放错误关闭；地板/树/草组合项不再有明显 `rework`；主景局部不靠远景模糊遮掩问题。每次只改有证据的高影响项 |
| P2 低细节远景 | 只修仍造成全图问题的水/暖岸轮廓、最远剪影与色彩层；不动主相机和已过关主景。局部岸石、芦苇和新增树不是默认任务 | 反投影 + 物件 ID 可见面积图 + 50% 全图 | 暗叶/暖岸/冷水/软远景四层可读，六锚点未被遮挡，全画面光色项可过；达到远景最低完成线即停止，不追求远景近看精度 |
| P3 完整验收与定点返修 | 重开 `.blend`；先查原尺寸主景、50% 全图和四组合项，再出正式渲染。只修仍可见的最高扣分项 | 原尺寸关键局部 + 50% 全图审图 | 四组合项、八硬门槛、六维自评逐项有理由；制作侧 ≥85 且每维 ≥3 才进独立盲评，失败则按差距返修 |

**修复单元仍是一项缺陷对应一个可证伪假设**，符合现行工作流；草茎漏变换、树盆错位和梯子缺支撑分别记录和机械核对。相互独立、已经通过便宜检查的修复单元可以合并做一次整图渲染，不再为一根草、一条岸线各完整重建一次。提交渲染批次前，先用投影和可见像素证实改动在目标屏幕区域真实出现；平涂轮廓与接地不过关，不花时间做 Cycles 品质渲染。P1/P2 各保留“前后同镜头 + 一个原尺寸局部 + 修改参数 + 命令/退出码/耗时/SHA”。每批只保留起点、有效终点和必要失败反例三类 `.blend` 检查点，避免为每次试数值复制约 100 MB 场景。

共享相机、灯光、景深或同一母版的修改不算相互独立，必须顺序验证。例如调光后重新检查地板与草的颜色，不能把旧材质通过结论直接沿用。每批用同一张对照板检查“目标项是否改善、已过关主景是否退步”，记录 improved/unchanged/worse；有退步则只撤回引起退步的改动。同一缺陷两次 unchanged/worse 就按上表换母版或结构方法；不靠连续微调同一个参数消耗轮次。

P1 虽集中修多个摆放错误，每个盆、树根和梯子仍分别输出机械检查结果；任何单项失败只回修该语义组，最后才做一次整图预览。草叶、树根、石板接缝和设施连接这些半尺寸图容易误判的部位，先做**100% 像素比例的小范围区域渲染**：保持最终相机和 1920×1078 分辨率，只设置区域边界，不移相机、不缩短焦距、不把小裁切放大当细节。局部图记录它在整图中的像素矩形，可用较低采样；它只验证局部形状和接地，不充当最终画质证明。远岸只在全图仍有问题时看局部，不为看不见的小石头做原尺寸渲染。P2 的远景三层先分别通过可见面积检查，再合成一次 50% 全图。这样保留问题归因，同时避免每个对象单独启动完整构建。

**效率目标是把同类返修的一次完整场景构建/预览控制在 4–6 次，完整 1920 图控制在 1–2 次，整体人工与机器耗时相对旧约 8 小时流程压缩 50% 以上。** 这是待实测目标，不保证固定工时；新流程第一次执行须记录每批壁钟耗时、无效试验次数和返修原因，再决定是否达标。若几何校验或评分未过，继续定点返修，但不重复已证伪的参数路线。

首轮计时预算按 4 小时试行：P0 对照板与源级检查 **25 分钟**，P1 摆放及 A/B 级主景质量 **100 分钟**，P2 低细节远景 **45 分钟**，P3 正式图/评分/封包 **50 分钟**，另留 **20 分钟**给最高扣分项的定点返修。远景直接制作预算占约 **19%**；这是初始工时分配，不是把远景评分权重改为 19%。如果 P1 的主景尚有明显缺陷，优先处理主景；P2 仍须完成最低背景线，不能直接跳过。每批记录 `design / edit / build / render / review / evidence` 六段壁钟耗时；哪段超预算，就根据失败证据换方法。**预算不允许覆盖质量门槛，也不能因到点而把失败标成通过。** 若草母版需要重做或评审返修超过预留，本轮可能超过 4 小时；记录实际差距并更新预计耗时，不能宣称已实现 50% 提速。所有批次沿用最小日志，不逐个物件生成一套重复报告。

## 4. 验收与交付

1. P1 主参考身份和 SHA 不变；相机、画幅、Standard 色彩管理先保持固定。背景轮廓方案若证明确需改机位，必须重新做六锚点与整图基线，不能暗改。
2. `placement_audit.json` 列出每个种植组根点与土床、硬物与承托的距离；失败项附可见图和源对象名。只把工程公差通过称为**摆放通过**，不冒充美术分数。
3. `BG_TARGET.json` 与叠图记录本轮编辑目标、深度层和对象，并引用 profile 中的 UI mask、原始截图依据与锚点；背景平涂及 50% 成图都须证明水、岸、树/地被、远景四层成立，不另维护第二套参考数值。
4. 正式渲染前做一次**全画面可见组巡检**：以固定图分区检查树/盆、三座草池、塔、桥、设备、梯子、台阶、栏杆、叉车、水岸和前景地被。按 `support / penetration / visual_overlap / material / no_issue` 记录，屏幕上看不见的 728 个零件不逐件人工评分；可见组有明显错误就定点修复，不先出完整图。
5. 最小交付仍完整继承工作流 §4：除 `.blend`、素材来源、profile 和报告外，包括 `blockout/color_key/combined/final/details` 图；已有证据只有源/相机/目标兼容且说明来源时才能复用，不把旧候选改名成新证据。方法与耗时汇总进 `REVIEW.md` / `DELIVERY.json`，不再另写重复总报告。
6. 交付绑定顺序固定为：保存最终源及依赖 → 重开该 `.blend` 生成唯一正式图 → 对正式图自评预检 → 对同一图 SHA 收集两份分开的盲评 → 写最终 `REVIEW/DELIVERY/GATE_REPORT` → 运行质量门禁。盲评拿主参考、当前最终图/必要局部和量表，不给制作侧分数或另一份评审结论作锚定；真实记录评审来源。源、相机或最终图变化后重新绑定并复评，不能在盲评后又渲染一张不同 SHA 的正式图。门禁只核验证据和算术，不能自动证明画面美观。
7. P0 即确认评审通道是否存在，P3 才实际提交盲评；通道不可用不能伪造独立报告或把同一制作自评抄两份。先完成制作候选与可检查证据，再按现行工作流报告真实外部依赖和已尝试替代途径。制作自评 ≥85、每维 ≥3、四组合项与八硬门槛通过才进入盲评；任何最终评审未过仍据反例修源。

最终机械检查在项目根目录运行 `python tools/static_map_quality_gate.py --candidate art/static_map/p1_autumn_courtyard/v09`（版本递增时同步参数）。**退出码 0 不等于达标**：当前脚本对有证据的 `blocked_external` 也返回 0；只有输出 `state: target_met`、`target_met: true`、`failures: []` 才表示当前门禁通过，且视觉结论仍来自真实评审。`repair_required` 按对应缺陷回到 P1/P2 返修；`blocked_external` 是未完成状态，不能包装成成功。方案阶段不运行此命令冒充新候选验收。

## 5. 确认后的第一步

只在用户确认本方案后：复核 v08 I53 源/图 SHA 与目录状态，取尚未占用的下一版本（当前为 v09；若已被占用则递增并同步本文路径）；完成 P0 的 profile 复核、全图目标/早期色块和摆放审计，再执行 P1 主景修复。**在确认之前不改 Blender 原生源、场景或渲染。** 现行工作流中“截至 2026-10-29 下一候选 v08”是过期示例，执行其“最高版本加一、不得覆盖”的规则。
