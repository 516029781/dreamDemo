## 绘图内容与当前制作流程是否匹配

**整体匹配。** 当前任务是“一张原创布局的静态秋日环境图和一个可重开的 Blender 场景”，而不是可玩的完整游戏。当前美术标准已把 P1 中可见的台阶/栏杆、统一石板平台、左侧树、右侧圆筒草池、中景设施和冷色远景，转换成了资产结构、材质、光色、缩图检查和局部检查要求。工作流再按先空间、再组合、后细节的顺序组织，方向是合理的。

| 当前关口 | 实际绘制工作 | 应留下的证据 | 通过前不要做 |
|---|---|---|---|

## 本轮流程修订与仍存缺口

### 1. 盲评已后置到制作侧预检之后

原流程要求制作者自评和两份盲评，但没有清楚分开返修阶段与最终评审阶段。v6.3 工作流、执行指南和 gate 已按以下节奏修订。preflight 仍由模型人工核对，尚未实现自动工具。

1. 每轮渲染后，制作模型先按 P1 标准自查，并人工核对文件、接地、相机和渲染记录。
2. 自查显示明显低于 85、任一维低于 3、组合检查或硬门槛失败时，直接修源并重渲；此时不启动盲评。自评只用于返修导航，不能作最终放行票。
3. 制作侧认为候选达到目标且机械资料齐备后，才对**当前最终图的 SHA**收集两份分开的盲评。两份都须独立达到 85、每维至少 3，且组合检查和硬门槛全过。
4. 任一盲评失败就按证据返修。返修产生新最终图后，旧盲评因 SHA 不同而失效；新图需重新取得完整的两份盲评。

质量 gate 现按制作侧预检结果分流：制作自评/组合项/硬门槛未过时，不要求先交盲评；预检通过后仍要求两份盲评。这样减少低质量中间稿上的重复审阅；能节省多少时间必须由 v06 的阶段日志实测，不能先承诺固定比例。报告里的两个 reviewer_id 和 blind 字段仍是自报信息，机械 gate 不能证明真实独立；报告不得把“格式与门槛校验通过”写成“独立性已被自动认证”。

### 2. 明确可行走只是后续扩展方向

当前工作流是静态画面制作，不含角色移动、寻路或真机验证。“未来可扩展为步行场景”表示保留合理的平台和空间关系，**不表示本候选已验证可行走**。本轮不加入导航网格、路径连通或玩法验收，也不得把静帧报告成可玩 Demo。

### 3. 不发明未经校准的数值条件

P1 的锚点框和颜色 ROI 是人工近似观察，不足以支持自动通过容差。profile 可以记录位置、面积、颜色关系和遮挡；没有可重复标注/校准依据的量必须设为 manual_only/not_run，交由固定机位的视觉对照。旧 target_layout_v04.json、style.json、regions.json 与相关旧脚本未经认证，不可用于 v06 自动 PASS/FAIL。

## 当前参数与条件的审阅决定

| 参数/条件 | 决定 | 原因 |
|---|---|---|
| 整图参考与 SHA | **保持不变** | 固定为 P1 t084；CW 图片不参加画面比较。 |
| 总分线 85/100 | **保持不变** | P1 标准的制作验收目标，不是像素相似度。 |
| 六维每维至少 3/4 | **保持不变** | 防止总分掩盖单一维度明显不足。 |
| 四项组合检查 floor/tree/grass/lighting | **保持不变** | 这些检查验证代表性资产是否能组成同一画面。 |
| 八项 P1 硬门槛 | **保持不变** | 对应前景台阶栏杆、右侧草池、统一地面、枝叶透空、草体量、中景功能结构、冷软远景和材质资源可用性。 |
| 色彩样本、锚点自动容差 | **不增加固定容差** | 现有数据不足以证明某个新数值正确；先在新 profile 中可复核标注，再按校准结果决定自动化。 |
| Blender 版本与交付范围 | **按当前工作流** | Blender 5.2.3；交付静帧、可重开源文件和必要证据，不添加完整游戏产物。 |
| 候选目录 | **按当前工作流使用 v06 或下一个未占用版本** | 不覆盖 v05 或已有冻结证据；开始前检查目录占用。 |

## 可执行结论

当前绘图方案的对象、制作顺序和静态图范围能够支撑 P1 目标；**不需要改变参考图、85 分线、逐维门槛或四项/八项检查数值**。需要落地的是：明确 UI/角色遮挡仅为参考 mask、澄清不验收实际可行走，以及将盲评后置到制作侧预检通过之后。
