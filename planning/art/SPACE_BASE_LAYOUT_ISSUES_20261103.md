## 0. 一句话结论

**渲染忠实还原了方案、机械验收也全过了，但方案在「核心区布局」这一层从一开始就偏离了用户的真实要求与三角洲航天基地实机地图——四室没有直接围合连通，中间被硬塞了环廊和中央设备体。harness 流程执行了，但它不检查「布局是否正确」，所以错误布局一路绿灯渲染了出来。**

## 2. 用户验收不通过的核心问题（按严重程度）

### P0-1 四室没有直接连通，中间塞了环廊 + 设备体

**用户要求**：周围 4 个核心区（离心、浮力、蓝室、黑室）**直接联通，没有中间的区域**。

**当前方案实际做的**（§2.2 / §3）：

```
  浮力 — 北环廊 — 蓝室
    |               |
  西环廊   [中央设备体100×50 实心]  东环廊
    |         (总裁坐顶9m)         |
  离心 — 南环廊 — 黑室
         （还多一条南花园带 240×30）
```

- 四室彼此**不直接相邻**，要经四条环廊（西 70×50 / 东 70×50 / 北 100×70 / 南 100×70）间接连通，环廊转角还不互通。
- 中间压了一个 **100×50 实心「中央设备体」**——这正是用户说的「有中间的区域」。
- 结论：**当前拓扑与「四室直接围合、无中间区域」相反。**

### P0-2 不符合三角洲航天基地实机地图

实机（`reference/_df_physx/hangtianjidi.bin` + 攻略截图，§8.3 已记录）的核心区是：

| 真实 | 当前方案 |
|---|---|
| 核心区约 230×160 m，水渠/围墙环绕 | 240×190，围墙代替水渠 |
| H1 离心（西南）、H2 浮力（西北）、H3 蓝室（东北）、H4 黑室（东南）四室**围合** | 四室被环廊+设备体隔开 |
| 总裁**中央四层悬空**，仅浮力/黑室可达 | 总裁 40×30 玻璃盒「坐在 9m 设备体顶」 |
| 四室之间无多余过渡区 | 中间多出 4 条环廊 + 1 个设备体 + 南花园带 |

「总裁悬空」被错误地表达成「加一个 9m 高实心设备体托着」，反而制造了用户明确不要的中间区域。

### P1-1 撤离路线不符合

**用户要求**：去撤离的路应该很长；最后丢包点就单独一块。

**当前方案**：搜刮 770m / 直冲仅 350m / 总裁支线 710m；撤离点是「南花园 → 引道 → 试车间」三段拼出，花园夹在离心/黑室下方当出口通道，不是「最后单独一块丢包点」。

### P1-2 室内陈设太简陋，不达标

- 物件预算约 **256 个实例 / 5 万面**，摊到 4 个 70×70 大房间，每室仅几十件，视觉上「空、乱」。
- 用户明确：每个核心区室内的东西**不达标，需要更丰富**。

### P2 harness 流程有盲区

- harness **执行了**（17/17 + D1–D5 + 复现），流程本身没偷懒。
- 但 `HARNESS_SPEC.json` 的检查项全是渲染质量/尺寸/风格/可读性门禁（G1–G8、W1–W2、S1–S7），**没有一项校验「布局是否还原真实地图 / 是否符合用户拓扑要求」**。
- 后果：需求在最前面理解偏了，harness 后面再严格也拦不住。

## 3. 用户明确要求（逐条，不可再走样）

1. 周围 4 个核心区（离心 / 浮力 / 蓝室 / 黑室）**直接连通**，**没有中间的区域**。
2. **只有浮力和黑室能去总裁**。
3. 去撤离的路**应该很长**。
4. 最后**丢包点就单独一块**。
5. 每个核心区**室内陈设要达标（丰富）**，不能简陋。
6. 整体要**符合三角洲航天基地**，对照已下载的 PhysX 模型与实机攻略。

---

## 4. 根因

1. **需求在最上游就被理解偏了**：把「四室直接围合」做成了「四角楼 + 环廊 + 中央设备体」。
2. **总裁的「悬空」被具象成「托高」**，引入了一个本不存在的中间设备体。
3. **harness 只管渲染质量，不管布局正确性**，错误布局得以一路通过验收。
4. **室内陈设标准定得太低**（256 物件 / 5 万面对 4 个大房间）。

---

## 5. 修复计划（顺序执行）

1. **读真实拓扑**：从 PhysX 模型（`tools/df_physx_*.py`）用**结构化数据**提取核心区各建筑的外轮廓、门洞、相对位置；对照实机攻略图（gamersky / 233），确认四室围合关系、总裁位置、撤离通道走向。
2. **出新拓扑图**：画一张「四室直接围合 + 总裁悬空（仅浮力/黑室进）+ 长撤离路 + 单独丢包点」的核心区拓扑，**先给用户确认**。
3. **重写规格**：改 §2 总平面、§3 连通、§4 撤离、§5 逐间陈设（陈设密度按「丰富」重定标准）。
4. **重渲染**：重建场景，走 harness 全流程。

## 6. 待用户确认的关键点（避免再次理解错）

1. 四室的**具体相邻关系**：谁挨着谁、每两室之间的门开在哪几面墙、是否两两都有直接门。
2. **总裁**的确切形态：中央悬空如何表达（空中连廊？还是直接竖梯上下）、是否仍只从浮力/黑室进入。
3. **撤离路线**：多长算「长」、丢包点放在哪个方位、路线是否强制经过全部四室。
4. **室内陈设密度**：每个核心区大约要多少件「高辨识度物件」才不算简陋。

## 9. v3.9 自检补记（2026-11-03 02:30）

> 这一节是**自检**的结果：不是对实机，而是对方案文档自己的算术和几何。**方法**：把门、环路、花园、坞内坐标写成走位图，跑最短路（`tools/check_dist_v38.py`），再把每条写死的尺寸代回几何验一遍。

### B1 距离是估的不是算的（P0，已修）

- **现象**：撤离写 386 m，实际逐段是 30+44+69.5+78.9+138 = **361 m**；房间互达写 88/148/254，三档口径互相打架（88 是门到门走外道、148 是中心到中心、254 又是第三套）。
- **改法**：全部改走位图重算，统一"中心到中心"：**60 / 134 / 194 / 310**；总裁捷径 60 → **109 m**（含两次 12 m 爬梯）。

### B2 坞内动线几何上不成立（P0，已修）

- **现象**：v3.8 写"6 m 宽直线通道 49 m"，但集装箱在 `v=+17`、木托盘在 `v=−22`，两者相距 **39 m**，夹不出 6 m 走廊；撤离点 `(217,−215)` 反算局部坐标是 `(89.7, 15.3)`，正好压在箱列线上。
- **改法**：动线改 **19 门内 + 60 坡道 + 8 平台 + 35 横穿 + 16 沿墙 = 138 m**；箱列移到 `v=+16`，`u=73..75` 留 2 m 箱缝当唯一通道口；撤离点移到 **`(221,−214)` = (u90, v+19)**。

### B3 总裁盒与屋顶穿模（P0，已修）

- **现象**：盒顶 16.5 m，四室墙顶 9–13 m，盒子有 3.5–7.5 m 露在墙外，但文档从没写屋顶开洞。
- **改法**：补 **40×30 采光井**（盒体投影），墙顶收边 + 0.6 m 女儿墙；导轨槽从井口向南北延伸到墙。

### B4 门、楼、平台三处对不上（P1，已修）

- **中控门 vs 中控楼**：门在 `x=120`，楼在 `x60..104`，错开 16 m → 楼挪到 `x98..142`。
- **"3.2 m 通高缺口"**：通高 = 到顶，墙高 9–13 m → 改"净宽 3.2 / 净高 6"。
- **撤离点"黄框" vs "平台 +2.4"**：两处写法冲突 → 黄框在坞底 ±0，+2.4 是旁边不可上的设备平台。

### B5 视觉规格缺三条硬约束（P1，已修）

- **不封顶剖切**：不写就会默认封顶，俯视只剩屋顶 → 明确剖切到墙顶，唯一封闭顶是总裁盒。
- **导轨 8 m = 56 px**：在纹理上会被读成第二条路 → 只画 2.4 m（17 px）亮线，结构槽压深色。
- **明度分层**：只给了水色 → 补四层（水 12–18% / 平台 45–55% / 建筑 60–78% / 标识 85–95%）+ 三种地面灰 + 最小可辨尺寸表。
