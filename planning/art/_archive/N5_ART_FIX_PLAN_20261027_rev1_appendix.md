# n5 美术问题与修正方案（2026-10-27）

输入：用户对 `game_finalN5h` 的 5 条反馈。基准：参考帧 `P1/t015s.jpg`、`P1/t084s.jpg`；现状帧 `delivery/next_cycle/n5/T3/game_finalN5h_formal_ui.png`。

一句话结论：**现在缺的不是精度，是"体量感"和"色相"。** 叶子和草都在用大量小尺寸几何去堆面积（细、碎、稀疏），而参考图靠少量大块体量铺满面积；同时调色板里混入了深橄榄与深褐，把整幅画面拉暗、拉绿，与参考的"暖琥珀＋浅金"偏离。

## A. 整体色调不像参考图

**现象**：画面偏暗、偏绿黄，缺少参考图那种被阳光照透的暖琥珀感。

**证据**（同一算法采样，见下表）：

| 图 | 平均明度 | 平均饱和 | 主导色相 |
|---|---|---|---|
| 参考 t015 | **44%** | **26%** | 0°(红琥珀) 71% / 30° 19% |
| 参考 t084 | **45%** | **25%** | 0° 69% / 30° 22% |
| 当前 n5h | **40%** | **22%** | 30°(橙黄) 65% / 0° 26% / **150°(绿) 3%** |

差 4-5 个明度点、3-4 个饱和点；色相分布从"红琥珀为主"偏成了"橙黄为主"，还多出参考图里几乎不存在的绿色。

**根因**：
1. 调色板把 `leaf_olive #5F5230`（H≈42°，L≈28%）和 `leaf_deep #5A3221` 放在树冠主卡片行里，两种暗色合计占 3/7；
2. `build_map001.py` 的主光与 `globals.ambient` 都按"压住过曝"调过，导致整体压暗；
3. 雾（`fogStart 26 / fogEnd 72`）用灰米色 `#C9C4B0`，把中远景的暖色洗成灰黄，进一步拉低饱和。

**方案**：
- 调色板：`leaf_ochre #B8702F → #C46A22`、`leaf_amber #9A5326 → #A85A22`（色相往 0-15° 拉，明度提 4-6%）；
- 主光 illuminance +12%，色温往 3200K 侧微调（当前偏中性）；`ambient.skyIllum` 12500 → 14000；
- 雾色改暖：`#C9C4B0 → #D8C6A6`，`fogStart 26 → 32`（让近中景更少被灰化）。

**结果表达**：画面第一眼像"午后斜阳照进庭院"，石面泛暖白、树叶透亮发金；自动化验收——平均明度 43-46%、平均饱和 25-27%、0°±15° 色相占比 ≥55%、120-180° 绿色 ≤1.5%。

**代价**：纯参数，0 三角形，1 次重建即可对比。

## B. 树叶应该是浅色的

**现象**：树冠读起来是深绿褐，参考图是浅金/琥珀色团块。

**证据**：树冠卡片配色行 `near_leaf = [0,1,2,3,0,4,2]`，其中 0=`leaf_olive`(#5F5230)、4=`leaf_deep`(#5A3221) 出现 3 次；`mass_mats` 里同样有 olive/deep/far 三种暗色。当前树冠区域平均明度约 35-40%，参考对应区域 55-65%。

**根因**：为了"有层次"，用深浅两套叶子交替，但暗色是**深绿橄榄**而不是**暗琥珀**，在暖光下不反光，显得脏。

**方案**：
- 把暗色从"深绿"换成"深琥珀"：`leaf_olive #5F5230 → #8A6A34`、`leaf_deep #5A3221 → #7A4A26`；
- 新增 `leaf_gold_light #E8BE72` 进入主行，把 `near_leaf` 改为 `[1,2,5,3,2,1,2]`（只有 1 个暗色位）；
- 树冠材质 roughness 0.56 → 0.48，让顶部受光更亮（代价：高光略强，需和 A 的曝光一起看）。

**结果表达**：树冠整体是"浅金＋琥珀"的块面，背光处也是暖棕而不是绿黑；自动化验收——树冠区域（画面中上部中央 300×300 取样）平均明度 ≥55%，绿色色相占比 ≤2%。

**代价**：0 三角形。

## C. 草和树叶都太细、很杂乱

**现象**：草像稀疏的针，树冠像撒了一层碎屑，近处看是噪点不是植被。

**证据**：
- 树干/树冠叶片 `leaf_size` 0.17-0.32m；绿篱 `leaf_size=0.115`、每簇 14 片（`build_map001.py:510`、`build_env_courtyard.py:438-524`）；
- 草：每簇 `count=14` 根细叶，`blade_width` 偏窄（`_add_grass_tuft`，`build_map001.py:264`）；
- 结果：叶片在 720p 下只有 2-4 像素，抗锯齿后变成灰点，既不高也不密。

**根因**：为了控三角形，选择了"多而小"；参考图是"少而大"——叶团靠**大卡片 + 少量**形成块面，屏幕上的覆盖率靠尺寸而不是数量堆。

**方案**：
- 叶片尺寸整体 ×1.8-2.2：树冠 0.17-0.32 → **0.36-0.62**；绿篱 0.115 → **0.22-0.26**；
- 每簇片数 14 → **6-8**，同时把簇半径略放大，保持体积不变；
- 草叶宽度 ×1.8（细针 → 窄叶），单叶分段 3 → 2。

**结果表达**：近景看得到成片的叶团轮廓和草叶宽度，不再是噪点；自动化验收——在 720p 下树冠区连通块平均面积 ≥ 当前 2.5 倍（用二值化+连通域统计），草叶最小宽度 ≥ 3px。

**代价**：**三角形大幅下降**（卡片数 ÷3、草叶分段 −33%），预计 −45%~−60%，正好为 D 的加密腾出预算。

## D. 草的位置很空旷，草丛应该铺满

**现象**：花坛和草坪里大片裸土，只有零星几根草，参考图里草是密不透风的干草堆。

**证据**：`N5_GRASS_BLADE_KEEP = 0.44`（**删掉了 56% 的草叶**）、`N5_GRASS_RING_BLADE_KEEP = 0.55`。这两个值是为压三角形加的"抽稀"，直接后果就是"空旷＋杂乱"——留下的草不成簇，看起来像插上去的。

**根因**：用"抽稀"解决三角形预算，而不是用"少而宽的叶片"。抽稀是随机删叶片，破坏簇的完整性。

**方案**：
1. `N5_GRASS_BLADE_KEEP` 0.44 → **1.0**，`N5_GRASS_RING_BLADE_KEEP` 0.55 → **1.0**（不再随机抽稀，簇完整）；
2. 单簇叶片 14 → **8** 根，叶片宽度 ×1.8、分段 3 → 2——用"少而宽"换覆盖，不再用"多而细"；
3. `_add_turf_patch` spread ×1.3、密度 ×1.2，让相邻簇互相压边（宁可重叠，不留缝）；
4. 花坛内侧加一圈"溢边草"（沿边缘 0.15m 内加密），消除盆口一圈空环；
5. 裸土材质明度略降（避免和干草抢眼）。

**结果表达**：花坛/草坪内几乎看不到裸土，草的边缘是"溢出"的而不是"种进去的"；自动化验收——草坪区域内褐色裸土像素占比 ≤5%（当前约 25-35%），草的覆盖轮廓无 >0.3m 的空洞。

**代价**：草 99,335 → 约 103,000 三角形（+4%）。覆盖度靠叶片变宽和簇变密拿到，不靠数量。

## E. 地板格式不统一

**现象**：同一块场地上出现了好几种石板尺度——中央大块、通道窄条、外围小方石，看起来像三个不同场景拼在一起。

**证据**：W4 为了"破除网格感"引入了三套铺法（`env001_layout.add_paving_module_style`）：`plaza` 每行 2-3 块、`path` 每行 5-6 块、`edge` 每行 9-10 块。参考 t015 全场是**同一种大石板＋一圈收边**，只有两级尺度。

**根因**：上一轮把"不自然"误判成"太统一"，于是加尺度来制造变化；但参考图的变化来自**石板本身的不齐整**（手切边、缝宽微差），而不是尺度混用。

**方案**：
1. 全场统一为 `plaza` 主格式（每行 2-3 块，板长 1.6-2.2m）；
2. `path` 与 `edge` 合并为**唯一的收边**：只在广场外圈一圈条石（每行 5-6 块）+ 路缘石，作为边界语言；
3. 保留 W4 已有的"四角独立内缩"（缝宽 0.010-0.020）与行高 ±26% 抽样——**不齐整感来自这里，而不是来自换尺度**；
4. 删除 5% 下沉磨损的第三套小方石。

**结果表达**：一眼读出"一个广场"，变化藏在缝宽和手切边上，不再像拼接；自动化验收——全场石板截面尺寸聚类 ≤2 类（当前 3 类），缝宽标准差 ≤0.004m。

**代价**：铺地三角形略降（大板更少块数）。

## 执行顺序

1. **B + C**（叶色与叶尺寸、草叶宽度）——一次重建，看树冠和草的体量是否成立；
2. **D**（草覆盖率）——在 C 的预算余量里加密，出对比图确认不是"变成一片糊"；
3. **E**（铺地统一）——单独一次重建，避免和植被改动混在一起无法归因；
4. **A**（色调/光照/雾）——最后调，因为前三步都会改变画面明度分布，先调色会白调。

每一步都出「同上机位 before/after 对比图 + 三项统计（明度/饱和/色相占比）」，不通过就回退该步，不叠加。

## 4. 需要你拍板的 4 个决策点

1. **树冠接受变"块状"吗？** 叶片从 17-32cm 放大到 36-62cm，数量减少 3.5 倍。换来体量感，代价是凑近看能看出是卡片。

## B2. 结构特征（照抄这四条）

**树叶**
- 单叶**可辨识**：参考里一片叶约占画面高度的 1.5-2.5%，叶形（掌状）能看出来；不是均匀噪点。
- **三级明度**：亮面 `#A87F63~#C7B698`（L52-70%）/ 中间调 `#956A48`（L43%）/ 暗腔 `#5A3522`（L27%）。三级比例约 **25% / 55% / 20%**。
- **有空洞**：冠内能看到天空和背景，空隙约占冠投影面积 **25-30%**，边缘是参差的单叶轮廓，不是光滑球壳。
- **边缘透光**：逆光侧叶子几乎发白金（P90 #C7B698），说明参考是"半透"处理。

**草**
- **细但长且密**：叶宽仅 2-3mm 级，但长度是花坛高度的 1.2-1.5 倍，密到看不见土。
- 颜色 **暖棕金**（#90684F 均值，亮部 #C18056），不是黄绿。
- 生长方向大体一致（微倾），成丛，不是随机四散。

**铺地**
- **单一尺度**：全场一种石板，长宽比约 **1.5-1.8 : 1**，板长约等于 3 个成年人脚长（≈1.2-1.6m）。

- **通缝为主 + 半砖错缝**：方向统一，不换向。
- 表面有**逐块色差**（P10 到 P90 跨 30 点明度），但**没有零星卵石**点缀。

## C3. 你提的 5 条，一条一条对

### ① 整体色调不像参考 → 有解，靠"逐材质校色"不是套滤镜
- 证据：树冠中位明度 56 vs 84、饱和 54 vs 37；暗部像素 58% vs 44%
- 根因（代码位置）：`PALETTE` 里 `leaf_olive #5F5230`（L28 深橄榄）、`leaf_deep #5A3221`；天空 `#C3D2D2`（冷灰绿）；冷补光 `#A9C2D6`
- 三档都改：树叶 5 个色标提亮去饱和、`leaf_mass`（冠内实心体 `#402C1F` L18，不提亮一直是黑团）、天空改暖米、补光去蓝
- 目标：树冠 P50 ≥ 72（B）／≥ 78（A）

### ② 树叶应该是浅色 → 有解，且必须动"内芯"不只动叶片
- 只改叶片颜色不够：冠内还有一层实心 `leaf_mass`，L18，直接决定暗部占比
- 三档：`leaf_mass` → `#5F4B38`（B）/`#6B5540`（A）/`#745C46`（C）
- 目标：暗部占比 58% → 45% 以内

### ③ 草和树叶太细、很杂乱 → 有解，这条最硬
- 证据：树冠 34.6 vs 13.9（2.5 倍）、草 31.1 vs 16.3（1.9 倍）
- 根因：为省三角形选了"多而小"——树冠叶 0.17-0.32m、绿篱每簇 42 张卡片、草 14 根/簇
- 关键公式：**覆盖满时，边缘密度 ∝ 1 / 叶片尺寸**（尺寸 ×k → 周长 ×k、面积 ×k²，密度只跟 k 走，与数量无关）
  - 降到 18 → k=1.9；降到 14 → k=2.5
- 三档：叶 ×2.0/数量 ×0.4（A）、×1.45/×0.72（B）、×2.9/×0.22（C）
- 副作用是好的：叶片数量降、每片仍 4 tri，**三角形跟着降**

### ④ 草的位置空旷、应该铺满 → 有解，但"回满"单独做会让体积爆掉
- 证据：草区近白像素 53.9% vs 24.8%（一半是亮底），且 `N5_GRASS_BLADE_KEEP=0.44` 删掉了 56% 的草叶
- 实测教训：只把草回满，地图 GLB 从 **93.4MB → 123.6MB**（+30MB）
- 所以三档都按"回满 + 加宽 + 减簇内根数"组合：宽 ×1.9、簇内 14→10（A）
- 目标：草区 `edgeDensity` ≤ 22、亮底占比 ≤ 30%

### ⑤ 地板格式不统一 → 有解，量化后是"板太小 + 三套尺度并存"
- 证据：每行暗缝 30 vs 21（板宽 0.7 倍）、缝对比 41 vs 30
- 根因：`plaza`（2-3 块/行）、`path`（5-6）、`edge`（9-10）三种语言同框
- 三档都统一为 plaza 语言，缝提亮 `#75685A → #9A8570`，缝宽 ×0.8
- 目标：每行暗缝 ≤ 24、缝对比 ≤ 33

## C6. 这套方案做不到的部分（先说清）

1. **树的模型结构不可能一样**：参考的树是真实枝叶模型，我们是用卡片叶拼的壳。能做到的是屏幕统计量接近（密度/明度/饱和/空隙），做不到同一个枝形。
2. **石材表面的磨损污渍**：参考铺地有贴图级污渍，我们 0 贴图，只能靠逐块颜色微差 + 3.5mm 高度差模拟。
3. **景深**：参考是 1920×1078 带轻微景深，我们 1280×720 无景深，远景的"糊"我们只能靠雾。
4. **物理尺寸 vs 屏幕等效**：要让屏幕观感对上，叶片物理尺寸会大于参考（0.34-0.64m vs 参考折算 0.09-0.14m）。若要物理等效，必须同时把相机拉近（y 11.5→9.2、fov 37.5→34），那是构图变更，需要你单独确认。
