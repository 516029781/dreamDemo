# P1 秋日静态地图制作流程

> 更新：2026-11-01，现行版本 v3。本文是当前制作链路的唯一执行规范。活动候选/工作单见 `planning/art/ACTIVE_STATIC_ART.json`；视觉目标与评分见 `P1_T084_ART_DIRECTION_STANDARD_20261028.md`；机器契约见 `CODEX_STATIC_MAP_QUALITY_HOOK_20261029.md`。旧流程和旧候选只作历史追溯。

## 1. 本轮目标和范围

- 交付一张 P1 秋日静态环境图、可重开的 Blender 源和绑定证据；不做角色、UI、动画、玩法、Cocos、微信包或真机测试。
- 唯一整图参考是 `reference/_raw_screenshots/P1/t084s.jpg`，SHA256 以美术标准为准。CW-8/CW-9 只用于地图数据和 Harness 结构研究，不用于画面造型。
- **当前图完全无植被**：禁止树、叶、草、花、灌木、苔藓、藤蔓、杂草、盆栽、土壤花池和植物贴图/模型。左侧原树区改为有功能的高型维护柜/设备组；右侧原草池改为封闭式圆筒过滤/储液设备。两组都需明确底座、接口、检修面和投影，不能以随机方盒填空。
- P1 原图仍是构图、石材、暖光、工业设施、近中远层次的参考。植物区域只记录为原图事实，不要求复刻；总分衡量“无植被改编画面”的完成质量，不因移除植物本身扣分，也不得声称植物细节与原图一致。
- 新候选使用未占用的 `vNN` 目录，任何冻结源/图/证据均不覆盖。

## 2. 一次连续执行的关口

| 关口 | 工作 | 最小完成证据 | 未通过时 |
|---|---|---|---|
| G0 锁定输入 | 读取 `AGENTS.md`、`START_HERE.md`、活动状态/工作单、本文、美术标准；核对参考 SHA、候选目录和冻结文件；确认本轮零植被。 | 输入清单、SHA、候选 ID、参考 profile。未校准指标标 `diagnostic_only`。 | 修清单或 profile；不能凭文件时间猜最新版本。 |
| G1 空间灰模 | 定地面连续性、台阶/栏杆、平台高差、两组设备替代体块、支撑/连接、遮挡、相机；盘点 Outliner、集合、实例/Geometry Nodes、材质与图像纹理中的植物资产引用。 | 固定镜头灰模；相机参数；悬空/穿插/支撑检查；源对象与引用清单为零植被。 | 先修布局、接地和轮廓，不做高精材质。 |
| G2 代表组合 | 同机位组合地面、台阶、两组主设备、中景设施、背景和光色；做全图缩略与必要局部。 | 一张组合证据板；`floor/structures/lighting/background` 四项 pass/rework。 | 一批只试一个主假设；同一方法两次无改善就更换方法并继续。 |
| G3 完整图与自评闭环 | 完整渲染；制作模型对绑定图片六维自评，再由同一制作模型逐维寻找“为何分数可能过高”的反例并确认/下调分数；低分即修复、重渲。 | 同源 `.blend`、`final.png`、六维自评和同模型反证自检、组合/硬门槛记录、隔离重开复现、REVIEW/DELIVERY/GATE。 | gate 输出修复项后，制作模型继续修改源并重渲；图片 SHA 变化时重做自评和绑定。 |

一次任务连续完成 G0–G3，不等待阶段审批，也不等待其他模型的独立终审。制作模型必须自己查看每张绑定图、指出反例并修复；独立终审不是当前放行条件。项目 gate 只核文件、SHA、评分算术和证据字段，不具备图像理解能力，不能代替制作模型看图。只有真实外部依赖阻断继续工作、且 gate 要求的替代尝试与证据齐全时，才能报告 `blocked_external`；缺少 reviewer、阶段意见或普通返修时间不是外部阻塞。

## 3. 返修方法

每批只验证一个主假设，在 `REVIEW.md` 记录：

1. 参考中可见的非植物目标特征、当前图的反例位置和图片 SHA。
2. 根因层级：几何/布局、材质/贴图、灯光/World、相机/合成或对象组织。
3. 要改的 Blender 对象/节点/参数，预期图像变化和验证局部。
4. 修改前后同机位图、相机/渲染参数、命令/退出码、耗时、源和渲染 SHA。
5. 结论为 `improved`、`unchanged` 或 `worse`；连续两次无改善要写明换了什么方法。

修复顺序：构图与接地 → 主体轮廓/空间层次 → 材质统一 → 光色纵深 → 局部细节。只使用有场景功能的箱柜、设备和建筑结构；数量少但轮廓、接触阴影、尺度、接口与组合关系清楚。不能通过改参考、改评分阈值、重算旧 SHA、加植物或堆无用途物件让检查通过。

## 4. 自评和自动质量门

- 现行评分为六维加权总分 `≥85/100`、每维 `≥3/4`；权重和逐维定义见 P1 美术标准。所有四项组合检查和八项硬门槛也必须通过。
- 自评必须绑定当前 `final.png` 和固定参考 SHA，逐维写至少 20 字符的可见证据；低分项必须有 `repair_queue`，字段包括缺陷、原因、动作、预期效果和验证方式。零植被门槛需同时附源对象/实例/贴图引用清点结果和最终图全画面检查记录，不能只报对象名搜索。
- 为降低自评分虚高风险，同一制作模型须对六维逐项执行反证自检：写出最可能的扣分反例、为何最终分数保留或下调、最终分数，并将自检绑定同一渲染 SHA。此自检不是第二个 reviewer，不暂停制作、不增加交接。
- gate 以 `p1-static-map-quality-gate/v3` 重新计算分数并核对哈希/复现。`rework_required` 不允许任务结束；修好后更新同一候选或按证据规则新建候选，重新渲染、自评与绑定，再提交 gate。
- `target_met` 还要求六维反证自检绑定同一图、无外部审核字段、`repair_queue: []`；有任何未解决修复项都不得结案。
- 没有独立 reviewer 字段、盲评要求或外部审核阶段。用户之后若明确要求我检查，属于额外的可选视觉复核，不是其他模型交接的阻塞条件。
- 重开隔离副本并复现正式渲染，输出 SHA 必须与最终图绑定 SHA 相同。微信真机和运行时性能不在这次静态图质量声明中。

## 5. 必需交付和按需证据

每个达标候选必须包含：

| 文件 | 必须包含 |
|---|---|
| `scene.blend` | 可编辑、资源相对路径正确、可独立重开的场景 |
| `renders/final.png` | 唯一正式静态图 |
| `reference_analysis/P1_REFERENCE_PROFILE.json` | 固定参考 SHA、画幅、锚点、遮挡/可比较区；未校准数值标 `diagnostic_only` |
| `REVIEW.md` | 六维自评分数及可见证据、返修日志、相机参数、真实限制 |
| `DELIVERY.json` | 源/图/参考/profile SHA、Blender 版本、复现命令/退出码、耗时和文件清单 |
| `GATE_REPORT.json` | v3 制作者自评、组合/硬门槛、复现与绑定；不含独立终审字段 |

灰模/组合过程图可并成一张证据板或嵌入 REVIEW。背景遮罩和面积统计、DOF 对照、独立细节板、色块图仅在本轮实际使用该诊断时交付。外部贴图/模型需包含源、导出文件与来源/许可记录。日志记录失败反例和返修决定。

## 6. 版本、复现和空间

- 从目录实际核对未占用的新 `vNN`。旧哈希绑定证据、冻结候选和固定参考不得覆盖或清理。
- 隔离复制候选、重开 Blender 并复现最终图；记录版本、命令、退出码、源/图 SHA。复制件须不依赖原目录外的临时资源。
- 运行 `python tools/static_map_quality_gate.py --candidate <candidate-path>`；gate 不会启动 Blender 或判断画面美术质量。
- 项目容量上限 15 GiB、12 GiB 预警；≥50 MiB 新增内容先做容量预检。结束清理只处理维护工具 dry-run 明确允许的可重建缓存。
