## 0. 平台限制（这一节 rev1 写错了，先说清）

| 项 | 官方当前值 | 说明 |
|---|---|---|
| 主包 | **≤ 4 MiB** | 硬限制，超了传不上去 |
| 主包 + 分包合计 | **≤ 30 MB** | developers.weixin.qq.com 分包文档（2025-05 更新）；英文版 PDF 仍写 20 MB，是旧值 |
| 单个普通分包 | 不限 | |
| 单个独立分包 | ≤ 4 MiB | |

**本项目实测**（2026-10-26 23:23 真实 `wechatgame` 构建 + `tools/maintenance/audit_wechat_package.py`，阈值 4.0 MiB）：

```
主包 179.74 MiB   分包 0   远程 0   → 未过 4 MiB 门槛（返回码 2）
构成：assets/resources 174.44 + cocos-js 3.54 + assets/main 0.92 + assets/internal 0.65
```

**关键推论（rev1 完全漏了）**：引擎三件套 **5.11 MiB 已经单独超出 4 MiB 主包上限**。也就是说：

> 即使把地图、字体、贴图全部搬进分包，主包仍然超标 1.11 MiB。**必须先裁引擎模块，这是所有风格方案的前置条件，和选哪一档无关。**

这也解释了为什么 rev1 里"C 档主包 9.9 MB ✅"是错的：那一列真正的口径是"整包"，不是"主包"。

## 3. 实现设计

### 3.1 一个总开关 + 输出隔离

```python
# build_map001.py
N5_STYLE = os.environ.get("N5_STYLE", "o")   # o=自有  c=卡通  r=写实
```

分叉只放在 4 个生成器里：`add_leaf_cluster()` / `_add_grass_tuft()` / `add_paving_module_style()` / 新增 `add_text_plate()`。

**输出必须分目录**：`art/candidates/<style>/...` + `delivery/next_cycle/n5/<style>/...`。rev1 没写这条，但 `layout.json` 的 `objects` / `merged_object` / `source` 字段会被不同档覆盖，三档共用一个目录会互相污染、无法回溯。

|---|---|---|---|
| 树冠 | 3×80 + 3×12 = **276 tri** | 60 卡 ×2 + 树干 = **500 tri** | 207k |

### 3.3 顶点格式（体积的真正杠杆）

实测：**3.35M 顶点 / 1.32M 三角 = 2.53 顶点/三角**，每顶点当前 40 B（POSITION 12 + NORMAL 12 + TEXCOORD 8 + COLOR_0 8）。这就是 140 MB 的来源。

| 项 | 现状 | C | R |
|---|---|---|---|
| POSITION | float32 12 B | 12 B | **int16 normalized 6 B**（KHR_mesh_quantization） |
| NORMAL | float32 12 B | **保留 12 B** | int8 normalized 4 B |
| TANGENT | 已关 | 不用 | 不用 |
| TEXCOORD_0 | float32 8 B | 仅文字牌 primitive | uint16 4 B |
| **COLOR_0** | **uint16 8 B（17.1 MB）** | **不要** | **不要** |
| 索引 | 7.9 MB | uint16 | uint16 |

两处修正：

1. **NORMAL 不能省**。glTF 规范允许省略（客户端算平面法线），但 Cocos 是否实现未验证；省掉在国内引擎上常见的结果是全黑或完全没有体积感。C 档保留 NORMAL，只靠"去 UV、去顶点色"省字节。
2. **位置量化不是"float16"**。glTF 没有半精度位置，只有 `KHR_mesh_quantization` 的 normalized int16/short。**必须先在 Cocos 里做一次支持性验证**（拿一个小 GLB 试），不支持就退回 float32——R 档要多付约 8 MB。

### 3.4 砖面白线的正确修法（rev1 的参数是错的）

rev1 写"`MORTAR_TOP` 从 −0.040 改到 −0.055"，两处都错：

- `MORTAR_TOP = 0.04` 是**模块空间的绝对值**，不是"板顶下的偏移"。实际 mortar 面在板顶下 **0.10 m**（`z_top − (SLAB_TOP − MORTAR_TOP)`，SLAB_TOP=0.14）。
- 再往下压 15 mm **没用**：mortar 顶面是水平面，照样正对主光受光，深度不改变亮度（场景无 AO）。

真正的成因（代码 `_add_slab`）：每块石板的**四个顶角各自独立 `rng.uniform(0, j)` 内缩**，而底部仍是足尺。所以

1. 单块板的侧面是"上小下大"的斜壁 → 缝是**向上张开的 V 形**；
2. 相邻两块在角部各自退让（最多 0.02+0.02+0.012 ≈ 0.052 m），角上开一个大口，露出 0.10 m 下的 mortar；
3. mortar 是亮色 `#75685A`（L42），水平面正对光 → 每块板 4 个白块，成排。

**修法（按优先级）**：

| 方案 | 做法 | 效果 |
|---|---|---|
| **A（推荐）** | 先按模块生成"列边界"和"行边界"坐标表，石板 = 相邻两条边界 ± 固定缝宽一半；相邻板共用同一条边界 | 缝宽恒定、位置不齐（不齐整感来自行高/列宽抽样），**不产生任何空洞** |
| B（最小改动） | `corner_jitter = 0`，只靠行列抽样制造变化 | 白块消失，缝宽均匀但位置不均，弱一档 |
| 必做 | mortar 材质 `#75685A`（L42）→ `#4A4038`（L26） | 缝变暗，接近参考的"浅而细的暗线" |

### 3.5 C 档必须自带一套光照（rev1 漏了）

现在的引擎光照是为半写实调的：主光 188,000 lux、强方向光 + 冷补光 + 雾。**平涂低模在这种光照下会发灰、发脏、塑料感**，和 KayKit 那种干净卡通完全是两回事。C 档要同时切：

| 参数 | 现在 | C 档 |
|---|---|---|
| 主光（key） | 188,000 | ≈ 80,000 |
| 环境光 skyIllum | 11,500 | ≈ 16,000 |
| 冷补光 | #A9C2D6 / 11,000 | ≈ #D8D8D8 / 6,000 |
| 雾 | fogStart 26 | 减半浓度或关掉 |
| 阴影 | 软阴影 | 硬阴影、分辨率减半 |
| 材质 | PBR | roughness 0.95、metallic 0、无贴图 |

**结论（rev1 的结论要改）**：

- **C 档 ✅**，主包 3.7 / 合计 9.4，余量很大（还能塞音频、角色、第二场景）。
- **R 档 ✅**，即使不做量化（合计 23.8 MB）也在 30 MB 以内；量化只为加载速度和多留余量。
- **O 档 ❌**，52–64 MB 是 30 MB 上限的 1.7–2.1 倍。**这是路线天花板，调参救不回来。**

> 20 MB 这个数字我们仍然当内部目标（比官方 30 MB 保守），但**真正的硬门槛是主包 4 MiB**，三档都必须先过引擎裁剪这一关。

## 5. 两件与风格无关但决定成败的事

### 5.1 字体子集化：40.9 MB → ≈1.5 MB

实测：`NotoSansSC-VF.ttf` 16.9 MB + `NotoSerifSC-VF.ttf` 24.0 MB = **40.9 MB**，比地图还大。全篇用字（UI + 对白 + 任务文案）不超过 600 字。注意两套都是**可变字体（VF）**，要先实例化（固定 wght）再子集化，否则子集工具会保留全部字形变体。

### 5.2 文字网格改贴图：27.3k tri → 8 tri

3 块指示牌 + 告示板标签目前把字形轮廓拆成三角面。换成 1024² 文字图集 + 1 个 quad：面数从 27,274 降到 8，**字节从约 2.9 MB 降到约 0.35 MB**。代价：极限放大时会看到贴图边缘（现在的矢量网格不会）。

> C 档**不追求与参考 ΔE 接近**——它本来就是另一种画风。它的验收是"干净、可读、体积小"。

| 三档共用目录互相覆盖 | 全部 | `layout.json` 字段会被覆盖 | §3.1 分目录输出 |
| 构建耗时 | 全部 | 实测微信构建单次 1 min 47 s，Blender 地图 3–5 min，加截图中转约 1 min | 三档串行约 20–25 min，不是 rev1 写的 15 min |

## 9. 需要拍板的 3 件事

1. **C 档模型来源**：A 只借造型语言、几何自己生成（默认，图集统一、体积最小）；B 真塞 KayKit 模型（要重做实例系统，工期约翻倍，贴图多 2–3 套）。
